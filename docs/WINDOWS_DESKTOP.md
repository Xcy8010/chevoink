## 已实现的范围

| 范围 | 实现位置与行为 |
| --- | --- |
| 原生壳 | `desktop/windows/src-tauri`；单实例、标准窗口、同源 WebView2、独立私有数据目录 |

| 更新候选 | 原生检查/确认、官方 updater 验签、固定下载源、24 小时自动检查间隔、开发版隔离 |

## 未完成的发布门槛

1. Authenticode 主体/渠道批准与签名配置。SignPath 资格待确认；不自行改变商业授权，不宣称获资助。
2. 受保护的 updater 私钥配置、完整签名发布作业、坏签名/中断/安装失败与跨版本更新实包验证。
3. 实际 Win11 安装、Cookie 登录与重开、IME、Blob 导出、上传、麦克风/WASM、听书、SSE 恢复、关闭保存及原界面对照。
4. Win10 22H2 低配真机、多屏/不同 DPI、干净环境缺 WebView2 的在线/增强离线安装。用户目前仅提供 Win11，不能将 CI runner 称为另一台真机。
5. 30 次冷热启动、10 轮窗口/任务切换、连续流和 60 分钟耐久的实际性能取样。
6. Rust 依赖/许可证审计及宿主攻击测试；完整真实 WebView2 自动化与故障演练。
7. 签名政策、公开隐私说明、卸载保留/显式清理验证、最终发布说明及 SBOM。
8. 经验证提交合并、正式 Windows Release、资产回下载验签、官网同摘要镜像和独立稳定清单，最后部署网页下载入口。

这些缺口不能用“网页四闸通过”替代。不得公开冒充稳定版，也不得为了通过验收停用签名、系统安全保护或减少原有功能。

## 运维原则

官网域名和 appId 不随版本变化；更新不清 Cookie、草稿、任务布局或审查。只更新壳时不重启生产 API。网页兼容改动需正常主线 CI/部署，生产任务中断需要该次有效授权。

正式资产按版本不可覆盖，保留当前和前一稳定版本及对应签名/摘要。故障优先停止扩大分发，再用更高版本的已知良好代码前滚恢复，不关闭版本或签名校验强制降级。

发布事故、密钥轮换、WebView2/Tauri 安全更新及隐私行为变化均需复验并更新本文；不将候选实现自动改写为已支持。
