最近核验：2026-09-08。代码与生产基线：`71f7adc`；[该提交 CI](https://github.com/Xcy8010/chevoink/actions/runs/34240086273) 已通过。本文描述已实现的系统及尚未完成的验收，不把规划、测试桩或代码行数当作产品效果。

## 1. 架构与入口

Chevoink 是 React SPA + Express + PostgreSQL 的单体应用，包含小说创作、阅读、社区与管理后台；Android 使用 Capacitor 壳。当前生产为 PM2 单实例，**不是已完成独立 worker / 多实例容灾的系统**。

| 层 | 入口与职责 |
| --- | --- |
| 前端 | `src/app` 路由；`src/features/studio` 创作；reader、community、admin 等按业务域组织 |
| API | `api/app.ts` 装配；`api/routes` 鉴权、校验、调用业务层；`api/lib/data` 数据访问 |
| 共享契约 | `shared/contracts`：请求、响应、SSE、章节版本、任务与账单契约 |
| Agent | `api/lib/agent/loop.ts`、`run-service.ts` 编排；`tools/registry.ts` 工具出口与治理 |
| 持久执行 | `runtime-identity.ts`、`runtime-lease.ts`、`runtime-state.ts`、`runtime-operations.ts`：身份、owner/epoch、检查点、操作回执 |
| 研究 | `research-sources.ts`、`research-ranges.ts`、搜索/读取工具：来源版本、分页、失败尝试、任务范围预算 |
| 计费 | `ai-service.ts` 用量与调用；`credits.ts` 钱包；`billing/` 价格、快照、预留、分项计算与回放 |
| 数据 | Prisma 6.12.0；当前 schema 106 个 model、72 个迁移目录，非覆盖率或质量得分 |
| 发布 | `scripts/deploy-production.ps1` + `deploy/deploy-production.sh`；nginx 与 PM2 |

固定运行时：Node **22.23.2**、npm **10.9.8**，以 `.node-version`、package engines、锁文件和 `runtime:verify` 一致性检查为准。生产实际 API 进程也校验 Node，而非只检查构建 shell。

## 2. 本轮修复与行为边界

| 用户问题 | 已实现的处理 | 不能据此宣称 |
| --- | --- | --- |
| 暂停/继续只总结、不干活、恢复旧章节 | 原任务请求与范围持久化；恢复预算及用量校验；停止信号贯穿辅助调用；迟到写入受 owner/版本限制 | 所有历史脏数据均可无条件自动恢复 |
| 连续性检查循环修订、文风被反复改动 | 校验复用绑定当前正文 revision 与来源；最多一次自动事实修订，之后只复核；警告不驱动文风重写 | 有事实错误仍可提交；缓存可跨版本使用 |
| 人类感检查偶发失败 | 对无法唯一定位的引用做一次局部校正；保留可定位意见；格式错误、provider/额度错误不再混成统一“未完成” | 引用无法核验时仍算通过；网络永不失败 |
| 新建作品被待审弹窗阻断 | 移除新建作品拦截；待审章节/计划按原作品持久化，修复切换时旧值误写入新作品 | 自动接受、拒绝或清空旧审查；全局取消其他保护 |
| 输入草稿、分栏状态串任务 | 任务作用域草稿/面板；恢复状态提交前禁止持久化到新作用域；StrictMode、A/B/A 与刷新回归 | 所有浏览器/真机组合已完成验收 |
| 大组件维护困难 | 提取草稿保存、布局、封面、目录、计划审查、消息投影、滚动和运行控制 | 拆文件等于包体缩小或交互变快 |
| 搜索/读取 404、乱码与重复获取 | 区分 provider 与目标错误；保存失败与 Retry-After；来源、正文和链接列表版本化；缓存分页复用 | 绕过网站访问限制，或已获得整本小说 |
| 计量/退款/重放不可靠 | 整数计算、不可变价格快照、幂等扣款/回执、退款意图持久化、未知用量待核 | 未知供应商结果均已自动核对；V2 已启用 |

创作区还保留待发送队列、调整方向、分支/新任务发送、待办/变更胶囊、移动端合并容器、窄查看器图标按钮、参数准备加载态等既有能力。本次重构不重新设计这些 UI。

## 3. Credits：现行公式与候选公式

### 3.1 历史 V1 基线

2026-09-08 折扣发布前基线使用 `credits-v1-exact`，旧操作保留该价格。下述已批准的 V2 通过有审计的生效费率卡启用。

定义 P = 确认的输入 Token，O = 确认的输出 Token，m = 本次冻结的档位倍率：

```text
C_v1 = ceil(1000 × m × max(P / 10000, O / 1000)) / 1000 Credits
钱包 milli = ceil(max(P, 10 × O) × multiplierBps / 100000)
m = multiplierBps / 10000
```

输入与输出是两个绑定池，取较大值，**不是相加**。内部 BigInt 先乘后除，每个逻辑计费操作只向上取整一次至 0.001 Credit；拒绝负数、非整数、未知和溢出输入。未知用量不能先填零再进入公式。

线上可选档位倍率快照：极速 **1.1**、标准 **1.0**、性能 **3.0**、极致 **3.5**。这是该日部署环境的配置，不是不可更改的源码默认值；以后以产品公示与操作价格快照为准。例如 P=10,000、O=1,000、m=1.1，收费 1.100 Credits，而非 2.200。

- 公测每日 450 Credits，UTC+8 15:00 重置；邀请奖励独立余额。
- 搜索每次 2 Credits，生图每次 6 Credits；退款引用原实扣记录。
- BYOK 文本不收平台文本 Credits；平台其他工具费用与调用权限分开判定。
- reasoning 已包含在确认输出总量时不重复相加；输入缓存命中不会在 V1 额外折扣。
- 供应商现金成本与用户 Credits 是不同口径，缓存命中率高不等于账单同比下降。

权威计算入口：`api/lib/billing/pricing.ts`、`api/lib/credits.ts`；调用价格绑定见 `billing/token-price.ts` 与 `ai-service.ts`。

### 3.2 缓存折扣 V2 与明确批准的发布例外

```text
U = P − H                 # H 为确认缓存命中 Token
N = U × inputNano + H × cacheNano + O × outputNano
钱包 milli = ceil(N / 1,000,000)
```

三项费率单位为 nano-Credits / Token，**已含倍率与校准，不得再次乘倍率**。缓存字段未知且缓存/输入费率不同，必须待核；两者费率相等时可按总输入计算。费率卡 draft → shadow → approved → active，保留事件与不可变 hash。

离线回放：`npx tsx scripts/audit-credit-pricing.ts <replay.json>`。输入为脱敏确认用量和冻结候选，不连接钱包、不扣款、不自动拟合或批准价格。

2026-09-08 产品负责人明确批准：缓存输入25%计价，普通输入/输出单价不变，`v1CeilingBps` 随价格冻结，最终取分项金额与原V1的较小值；验证后启用，豁免7天等待。快速审批仅允许此固定折扣，核对线上倍率、封顶、回放hash、质量及批准引用，仍需超级管理员、公示和生命周期事件。不是完成7天影子验证，也不证明供应商现金成本下降。其他改价仍走原门禁。

账单/用量页显示原费率和封顶；缓存未知不填零，进入待核。旧操作保留原快照。新费率启用后不能直接回退到不识别封顶字段的旧应用，应前向修复或先制定价格/协议兼容回退步骤。

本次离线回放（截止2026-09-08 15:40 UTC）：6,570条观察中，仅51条极速请求具备完整确认回执，V1为446.341、带封顶V2为284.069 Credits，单次最大涨额0。其余6,519条因历史确认/缓存字段不足排除；不改旧账，不外推到其他档位或供应商现金成本。报告hash：`0670d947df573eb9228f7c446e7a3b4f7d8995145c4a5d6c756c5e374c1e221b`。

## 4. Token 与时间优化：做了什么、效果到哪里

| 机制 | 减少的浪费 | 限制 |
| --- | --- | --- |
| 当前版本校验/质量报告复用 | 相同正文与来源重复调用模型 | 新 revision 必须失效，失败报告不能冒充成功 |
| 一次最小事实修订，随后只读复核 | 检查→改写→再检查的无界循环 | 真实错误保留阻断，不为省钱降低标准 |
| 无法定位的引用局部纠错 | 一条坏引用导致整份报告重跑 | 只在异常时增加最多一次校正；不保证单次必定更便宜 |
| 正文与链接列表持久化、游标分页 | 重复下载相同来源/重复重建目录 | 读取覆盖不等于逐章分析完成 |
| 失败记录、负缓存、Retry-After | 对受限/失效站点盲目连打 | 不能突破访问权限，不能把简介当正文 |
| 确定性收据与上下文压缩 | 久远工具参数/输出反复进入上下文 | 保留目标、约束、最新工具对与回读依据 |
| 原任务根预算与去重读取进展 | 暂停/重试刷新搜索额度、无 todo 提前退出 | 新普通任务搜索2/获取2，明确深度研究5/8；连续两次读取失败停止新增联网，缓存续读不耗获取额度；完整拆书预算仍未完成 |
| 操作回执、幂等记账、退款意图 | 重放重复付费、取消后丢退款 | 未知供应商用量对账仍有待完成部分 |

**结果边界**：故障测试证明上述控制流和不变量；目前没有发布后同任务、同模型、同预算配对的 Token/P95/质量统计，不能给出“节省 X%”或“速度提升 X 倍”。没有降模型、缩正文或绕过质量门来制造降本数据。

## 6. 发布、恢复与安全

流水线：固定运行时 → `npm ci` → Prisma generate → 隔离库角色/URL 校验 → migrate → check → lint → coverage tests → Agent eval → build → 两类依赖 audit。

发布使用 `git archive HEAD`，必须绑定 CI 成功的同一 SHA，不能打包未提交草稿、密钥或私有调查文件。远端当前仍原目录安装依赖、迁移及构建，再 PM2 重载；保留旧 hash 静态文件，最后发布 index.html。**尚不是完整不可变 release 目录/原子应用切换/自动回滚部署。**

`-SkipLocalChecks` 仅用于该 SHA 已通过受控远端等价门禁且得到授权的场景，不是跳过验证。停止运行中的 Agent 必须获得部署中断授权，暂停与迟到结果边界不能绕过。

认证区分 verified / missing / unavailable；无法核实返回 `AUTH_SESSION_UNAVAILABLE`，不把数据库故障当“未登录”而清 Cookie，也不把未知状态视为已验证。入口见 `auth-session.ts`、`api/app.ts`。

其他控制：章节 revision 条件写入、用户/作品归属、私有附件鉴权、受控出网与重定向校验、大小/时间预算、CSP enforce、HttpOnly Cookie、AES-256-GCM 模型密钥、后台审计。权限过滤是应用层约束，不等于 OS 沙箱。独立渗透验证和恢复演练不能由“audit 0 漏洞”替代。

数据库只做前向兼容迁移；回退代码不能直接 down schema 或删除已提交用户数据。备份还原一致性、RPO/RTO、跨版本任务恢复与回退演练尚待验收。

## 7. 尚未完成的收口

- 全仓 lines/statements ≥40%、关键模块逐项 lines/branches ≥80%、API/data 整体验收；目前仅有防倒退下限。
- 更完整的前后端职责边界、依赖/循环检查，以及所有 Work/IDE/移动端/阅读/社区/管理路径的端到端验收。
- 完整授权小说的章节清单、每章分析回执、缺章恢复与全书报告端到端；“已读范围”不能代替此项。
- “先研究再写作”的阶段授权、研究总预算策略与完整成本归属。
- 未知供应商用量自动核对、全部计费并发/恢复/对账场景，以及 V2 的分组影子和上线批准。
- 独立安全评审、数据库还原、跨版本回退、不可变应用发布、真实性能与文学质量非劣验收。
- 产品盲评、留存、付费/支付完整商业链路；仍应按公测而非已验证商业正式版描述。
