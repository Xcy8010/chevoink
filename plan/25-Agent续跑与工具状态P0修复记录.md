# Agent 续跑与工具状态 P0 修复记录

日期：2026-09-05。范围：主循环工具准入、任务续跑/检查点、Work 聊天轨道；不改作品正文、不充值、不更换供应商。

## 根因与改动

1. 流式 `tool-call-start` 在完整参数/熔断判定前就发出 `tool.call`，但拦截分支没有结果事件。统一在工具准入后才发执行事件；参数生成继续支持只读草稿预览。轮末清理草稿、兜底结算旧版悬挂卡片；其他工具共享同一修复。
2. 原签名截取字符串前 200 字、数组前 20 项，可能把不同修订误判相同。改为完整规范化 JSON 的 SHA-256；成功结果在同运行内缓存，重复调用在执行前拦截并向模型回填已有结果。失败可重试；真实写入后允许重新读取和校验新状态；待办原子推进、外部任务轮询与提问分别处理。
3. 输入“继续”创建新 run，却不恢复后端待办和原 TaskSpec。现在明确的续跑指令继承同用户、同作品、同会话上一任务的目标及约束；新请求不继承无关待办。
4. 防早停原为整次 run 共用 4 次提醒，用尽即使未完成也可成功。改为连续无新进展计数，有新结果会重置；待办未完成、只说下一步、响应截断、续跑未建立进度清单时不直接成功。重复无进展安全失败，保留未完成项，禁止提示模型假标 completed。
5. 检查点原增量为 100 万 Token，现为 200 万；初始默认 200 万，单次运行累计预算上限默认 500 万，轮次增量 50，自动续跑次数上限 4。检查点必须有真实差异或新的完成项；空改动不计进展。预算入口覆盖无工具/协议纠偏重试，到上限不能反复领取无效切片，耗尽后不再请求模型收尾。检查点提示持久化失败不再静默忽略。
6. 轨道预览被 Work 折叠列的 `overflow-hidden` 裁掉，只剩投影。改为固定定位 Portal，挂载 body 或当前全屏根；限制视口边界；支持鼠标与键盘，Esc、滚动、缩放时关闭过期定位。

## 预算与停止条件

- 200 万是主循环累计请求预算片，不是模型上下文窗口，也不是无限保证。请求完成后才能得到供应商实际用量，边界请求可能超出剩余预算；不会在已知预算耗尽后继续发起主循环请求。
- 子 Agent、Critic 与会话整理有各自调用及现有额度保护；本改动没有把主循环用量宣称为整个产品的统一计费硬限额。
- 保留用户停止、审批、应用 Credits、供应商错误、墙钟和防循环限制。线上只读聚合证实：近期“继续”请求存在仅 1 轮就 completed 的记录，也有供应商余额不足和应用额度耗尽的中断；余额问题不能通过强制续跑修复。
- 正常推进可跨阶段继续；无进展、资金/权限或服务故障必须如实停止，不伪造完成，不自动扩展原任务授权。

## 回归与发布要求

- 真正运行 `executeAgentRun`，模拟供应商与持久化边界：重复调用无事件、失败重试、新版本校验、恢复待办/原目标、超过 4 个阶段继续、预算重试入口、检查点硬顶、批量重复后仍有新工作、待办原子推进。
- 前端事件回归：轮末悬挂工具结算及草稿清理。UI 回归：Portal 不在裁剪列内、键盘/Esc/窗口变化。
- Playwright 本地模拟作品浏览器验证浅色/深色/全屏，预览卡实测 320×142px、定位在轨道右侧；截图位于 `output/playwright/agent-rail-*.png`（不包含真实作品）。
- 发布前运行 TypeScript、全部测试、生产构建、ESLint；CI 用独立 PostgreSQL 补全本地缺失的数据库集成测试。部署前确认活动任务，保留应用/静态资源回滚包；发布后核对 API 健康、在线资源与后端源码哈希。
