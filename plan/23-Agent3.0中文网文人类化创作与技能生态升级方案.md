# Agent 3.0 中文网文人类化创作与技能生态升级方案

> 文档类型：产品方案 + 技术架构 + 评测与灰度计划  
> 立项日期：2026-08-28  
> 适用范围：Chevoink 创作区 Work / IDE / 手机端、Agent 编排、Skills、故事记忆、计划与章节生成、质量评测  
> 核心目标：把 Agent 从“会生成通顺小说文本”升级为“会研究、会规划、会按中文网文规律创作、会自证质量、可被作者持续训练的创作系统”

---

## 0. 执行摘要

Agent 3.0 不应被定义为一次“去 AI 味提示词升级”，也不应把希望押在一个更大的小说全文向量库上。当前留存问题来自一条完整链路的缺失：Agent 不知道目标读者在期待什么，不先建立本书独有的创作判断，写作 Skill 没有稳定触发，写前没有场景级因果设计，写后又缺少针对中文网文的证据化质量门。因此，即使基础模型语言流畅，也会稳定地产生“华丽但不推进、情绪正确但不具体、章节独立可读但长篇衔接机械”的文本。

本方案的核心决策是建设六个相互约束的系统，而不是继续堆一段总 Prompt：

1. **创作研究台（Research Dossier）**：在新书、换题材、重大情节弧或作者明确要求时做一次有边界的题材与读者研究，结果沉淀为项目资产；普通续写不重复联网。
2. **合法文笔库（Craft Library）**：不把“全文相似检索 + 仿写某作者”作为产品能力，而是建立“合法来源原文 + 技法卡 + 风格统计画像 + 作者自有样章”的分层知识库。
3. **Skill OS 3.0**：采用类似 Codex 的元数据发现、按需触发、完整加载主说明、继续按需加载参考资源的渐进披露机制；Skills 可版本化、测试、启停、回滚，支持作者和 Agent 创建。
4. **场景驱动写作管线（Story Compiler）**：从读者承诺、人物欲望、阻力、选择、代价与状态变化生成场景任务包，再写正文；不直接从一句题材描述跳到完整大纲和章节。
5. **人类感质量系统（Humanity & Story Quality Gates）**：检测文风割裂、孤立华丽词、描写挤占剧情、抽象情绪、同构句式、角色声口趋同、因果跳跃和衔接断层，输出证据位置和最小修订，而非“一键同义词替换”。
6. **中国网文评测与反馈飞轮**：以专家盲评、作者修订成本、前三章留存、继续创作率和发布率为主指标；“AI 检测率”只作弱信号，不能成为发布门。

建议按 P0–P5 推进。第一阶段先修复“Skill 实际不工作”和“没有质量基线”这两个根因；在没有评测基线前，不应先投入大规模语料采购、微调或多 Agent 编排。

## 1. 现状审计：Agent 2.0 为什么没有解决问题

### 1.1 当前已经具备的基础

现有实现并非从零开始，以下能力可以直接继承：

- 单主控 Agent + 工具注册表；
- TaskSpec、UserDirective、上下文检查点和会话原文按需追溯；
- 卷章结构、章节 revision、ChangeSet 与回滚；
- L0–L3 故事记忆、证据来源、冲突状态和 RRF 召回；
- Draft / Critique / Revision 的初步隔离；
- Work / IDE 双工作区和移动端创作入口；
- Agent 2.0 功能开关和基础评测场景。

这些能力解决了“能不能安全持续写”的工程问题，但尚未解决“为什么值得读”的创作问题。

### 1.2 已确认的 Skill 断层

当前 `api/lib/agent/skills/index.ts` 只有 5 个硬编码 Skill，Router 主要依赖 `TaskIntent + 正则关键词 + phase` 打分，最多返回 3 个候选。系统上下文只告诉模型“需要时调用 `skill_load`”，没有确定性的装载策略、使用回执和质量闭环。

尤其关键的是：

- `prose-specificity.v2` 只支持 `revise`，不支持首次 `write`，所以用户一句话要求写正文时，“去机械化/具体化”能力不会进入 Draft；
- 路由正则中的“写/续写”过宽，容易把多个泛化 Skill 同时列为候选，却不能判断场景、题材和真实缺陷；
- 候选出现不等于 Skill 已加载，更不等于生成时遵守；当前没有“本轮为何触发、是否加载、使用了哪一版、是否改善”的产品与观测证据；
- Skill 无数据库实体，不能由用户创建、按作品启用、版本锁定、测试、回滚或灰度；
- 前端只有“作品 / 上下文 / 变更 / 记忆”，没有技能管理与运行解释界面。

因此，作者的判断是成立的：Agent 2.0 虽然“存在 Skills”，但不能像成熟 Agent 系统一样稳定地发现、加载和执行它们。

### 1.3 当前写作知识卡反而会放大公式感

`api/lib/agent/knowledge/writing.ts` 中的静态通用卡长期注入，并包含“每章结尾必须留钩子”“开篇 300 字内必须……”“对话必须至少承担一个功能”等强表达。这些规则本意是避免水文，但它们存在三个问题：

1. 对所有题材、章节功能和作者风格一刀切；
2. 将编辑经验写成逐章硬模板，模型最容易机械复现；
3. 常驻上下文让“平台统一腔”压过本书已经形成的声音。

Agent 3.0 必须把它们从常驻硬规则改为“按题材、场景功能和证据触发的软质量信号”。例如“没有章末悬念”不应自动判错；只有该章承担连载拉读任务、且没有任何未完成动作、信息差或情感余波时，才提示读者拉力不足。

### 1.4 用户指出的四类问题对应的系统根因

| 表象 | 直接根因 | 3.0 对应能力 |
|---|---|---|
| 前后文风割裂 | 没有滚动风格画像；每章使用相同通用 Prompt；修订常整段重写 | 风格指纹、分段漂移检测、最小范围修订 |
| 华丽词和特殊词异常 | 模型偏好显眼修辞；缺少语域铺垫与意象链检查 | “孤立精致”检测、题材感知词汇异常、修辞预算 |
| 描写多、剧情少 | 从“写 3000 字”直接生成，没有场景状态变化约束 | 场景任务包、剧情推进账本、段落功能分类 |
| 情感虚浮 | 只给情绪标签，没有具体欲望、身体代价、关系后果和生活经验锚点 | 情绪因果链、角色经验库、关系余波与可观察证据 |
| 长篇衔接机械 | 只注入摘要与上一章，没有明确“上一章终态 → 下一章开态”桥 | Chapter Bridge、未完成动作、知识状态与情绪余波 |
| 人物像同一个 AI | 角色卡记录事实，不记录语言行为样本与回避方式 | Character Voice DNA、对话归属盲测 |
| 改几轮仍像 AI | 修改仍由同一泛化标准驱动，常变成同义替换 | 独立评论器、证据化问题、局部修订、专家偏好数据 |

## 2. 调研结论与可行性判断

### 2.1 Codex Skills 值得借鉴的不是目录格式，而是上下文纪律

OpenAI 的 Skill Creator 将 Skill 定义为包含 `SKILL.md` 和可选 `scripts/`、`references/`、`assets/` 的自包含能力包；触发主要依赖名称与描述，主说明触发后加载，扩展资料按任务需要继续加载，并强调避免深层引用和上下文膨胀。[OpenAI Codex Skill Creator](https://github.com/openai/codex/blob/main/codex-rs/skills/src/assets/samples/skill-creator/SKILL.md)

OpenAI Skills API 还提供 Skill 创建、默认版本指针和不可变版本管理，这说明“Skill 是可版本化产品资产”，而不只是系统 Prompt 里的一段字符串。[OpenAI Skills API](https://developers.openai.com/api/reference/go/resources/skills)

适用于 Chevoink 的结论：

- 每轮始终只暴露轻量 metadata；
- 命中后完整加载主工作流，避免“读一半规则”；
- 题材参考、案例、检查脚本继续按需加载；
- 一次只激活少数互补 Skill；
- 每次运行记录版本、触发原因和结果；
- 副作用能力必须有权限与确认，第三方 Skill 视为不可信内容。

### 2.2 长篇质量不能靠一次生成

Re³ 使用“总体计划 → 递归注入当前故事状态 → 多候选重排 → 一致性修订”，人评中相较同模型直接生成，在整体情节连贯和前提相关性上取得明显提升。[Re³](https://arxiv.org/abs/2210.06774)

DOC 进一步采用详细分层大纲和段落级控制；论文报告相对 Re³ 在情节连贯、提纲相关和有趣性上分别获得 22.5、28.2、20.7 个百分点的绝对提升。[DOC](https://aclanthology.org/2023.acl-long.190/)

LongWriter 的 AgentWrite 也采用先规划、再拆分子任务写作的方式构造超长输出，并指出“能读很长上下文”不等于“自然地产出高质量长文本”。[LongWriter](https://arxiv.org/abs/2408.07055)、[开源实现](https://github.com/THUDM/LongWriter)

适用于 Chevoink 的结论：不要把一卷或一章当成一次 completion；应先生成可审阅的场景任务包，正文按场景写，再进行跨场景衔接和一致性检查。

### 2.3 “AI 率”不适合做唯一或主要 KPI

现有 AI 文本检测在改写、不同模型和不同文本分布下不稳定，甚至存在将人类文本误判为 AI 的风险。[Can AI-Generated Text be Reliably Detected?](https://arxiv.org/abs/2303.11156)

中文主观写作偏好同样不能被普通打分模型可靠覆盖。WritingPreferenceBench 含 600 对中文偏好样本；其报告中，普通序列奖励模型和零样本 LLM Judge 在去掉客观质量线索后接近随机水平，而带显式推理的生成式评审显著更强。[WritingPreferenceBench](https://arxiv.org/abs/2510.14616)

2026 年的 ChangJuan 面向中文书长故事，采用元数据、读者评价、分方面共识与长度—细节平衡摘要进行评估，并显示长篇评价需要题材感知的分方面权重，不能只读一小段打总分。[ChangJuan](https://aclanthology.org/2026.findings-acl.2044/)

适用于 Chevoink 的结论：

- “AI 检测概率”只做实验观测，不作为作者文本的真伪裁决；
- 核心门禁应是专家盲评、同题 A/B 偏好、具体缺陷证据和真实产品留存；
- 自动评审必须按题材和任务动态生成量表，且保留人工抽检。

### 2.4 现成“现代中文优秀网文商用文笔库”基本不存在

调研到的主要资源如下：

| 资源 | 可借鉴价值 | 许可结论 | Chevoink 决策 |
|---|---|---|---|
| [GuoFeng Webnovel](https://github.com/longyuewangdcu/GuoFeng-Webnovel) | 14 类中文网文、连续章节、多语对齐 | 明确仅限非商业研究，禁止修改与再分发 | **不得接入商业文笔库**；只参考其文档级组织方法 |
| [GenWebNovel](https://github.com/hjzhao73/GenWebNovel) | 中文玄幻/历史章节实体标注 | 不分发正文，本地重建仅限研究且受来源平台条款约束 | **不得作为正文库**；可参考实体标注 schema |

| [Novel Architect](https://github.com/zhougz520/novel-architect) | PREPARE→WRITE→REVIEW→COMMIT、12 类质量信号、确定性状态门 | Apache-2.0 | 可重点参考工作流、状态门和测试方法，保留 attribution |
| [神笔写作](https://github.com/qgming/ainovelstudio) | Skills UI、按需加载、市场研究与项目 canon 结合 | 页面未发现明确许可证 | 只做产品研究，不复制代码、Prompt 或资产，除非后续取得明确授权 |

中国现行《生成式人工智能服务管理暂行办法》要求训练数据具有合法来源、不得侵害知识产权，并要求提升数据质量；著作权法保护文学作品及复制、信息网络传播等权利。[国家网信办](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)、[中国人大网](https://www.npc.gov.cn/c2/c30834/202011/t20201119_308796.html)

结论：Chevoink 可以建设文笔库，但第一版不应采购或抓取“几万本热门现代网文全文”后直接做 RAG。最佳可行路径是合法来源分层、技法抽象、作者自有材料和平台内自愿授权。

## 3. Agent 3.0 产品原则

### 3.1 八条不可违背的原则

1. **剧情状态变化优先于漂亮句子**：每个场景必须改变至少一种状态，但不要求每段都制造高潮。
2. **证据优先于标签**：“情绪虚浮”必须指出原文位置、缺失的因果或后果，不能只打一个分。
3. **作者风格优先于平台统一风格**：通用 Skill 只做底线保护，不把所有作者修成同一种腔。
4. **题材和章节功能决定标准**：硬科幻使用“量子”不应被判 AI；日常校园文无铺垫高频使用才提示语域异常。
5. **研究按需触发并沉淀**：不每章联网，不每轮重复搜榜。
6. **Skill 必须可观察**：用户能看到启用了什么、为什么触发、用了哪一版、产生了什么影响。
7. **文笔库不提供在世作者一键克隆**：只提供高层技法和复合风格维度。
8. **评测先于扩张**：任何新 Skill、模型、语料或工作流，未通过同题盲评不得成为全量默认。

### 3.2 不承诺不现实目标

Agent 3.0 不能保证“任何专家都无法辨认 AI”，也不以规避平台检测为产品卖点。可承诺的是：显著减少可解释的机械模式，提高人物、情节、情感和长篇连续性质量，降低作者把章节改到可发布状态所需的轮数和时间。

## 4. 总体架构：Creative Intelligence Stack

```text
作者目标 / 当前作品 / 当前选区
            │
            ▼
Task Classifier ──→ 是否需要研究 / 规划 / 写作 / 续写 / 改稿 / 审阅
            │
            ├── Research Dossier（低频、可缓存）
            ├── Skill Router（metadata 常驻，正文按需加载）
            ├── Story Memory（事实、关系、知识状态、伏笔、风格）
            └── Craft Retrieval（技法卡、风格统计、作者样章）
            │
            ▼
Scene Task Builder（目标/阻力/选择/代价/信息变化/承接）
            │
            ▼
Draft Writer（受控但不模板化）
            │
            ├── Deterministic Checks（重复、长度、词频、状态、引用）
            ├── Story Critic（因果、人物、情绪、读者拉力）
            └── Style Critic（漂移、修辞、语域、声口、AI 纹理）
            │
            ▼
最小修订 / 候选重排 / 作者审阅 / 写入 ChangeSet
            │
            ▼
Post-write Commit（章节桥、故事记忆、风格画像、质量报告、反馈）
```

默认仍采用“单主控 + 按需专家”，不把所有任务升级为多 Agent。只有高价值写作、深度审阅和重大规划才调用独立 Writer/Critic；简单改句、标题和事实修正仍走单调用路径。

## 5. 合法文笔库：不是“小说全文向量库”

### 5.1 四层数据结构

#### L0：公共技法知识

来源于公开写作理论、内部编辑经验和可复用的结构方法。保存的是方法，不是小说片段，例如：

- 场景目标—阻力—选择—代价；
- 对话中的目的、回避、潜台词与权力变化；
- 悬疑信息释放与公平性；
- 都市生活细节如何与人物经济状态一致；
- 长篇衔接中的动作、知识和情绪余波。

#### L1：公版/宽松许可文学语料

只接入逐作品权利明确的文本。用途主要是提取：

- 句长和段长分布；
- 叙述/对话比例；
- 功能词与标点习惯；
- 叙事距离、视角稳定和时间组织；
- 意象如何跨段落形成链，而不是只摘“漂亮句子”。

古典、公版语料只能服务相应题材维度，禁止将其默认混入现代都市、校园、职场网文。

#### L2：平台授权与作者自有语料

来源包括：

- 作者上传并明确同意用于本作品风格学习的样章；
- Chevoink 站内作者单独 opt-in 的公开作品；
- 与版权方签署商业授权的现代中文网文；
- Chevoink 自建、由签约作者撰写的题材样章和正反例。

默认作用域应为“仅本作者 / 仅本作品”，不得把 A 作者私有样章召回给 B 作者。若作者允许进入平台公共技法库，应有单独协议、退出与删除机制。

#### L3：抽象技法卡与风格画像

这是运行时主要检索层。原文经过离线分析后，生成不含可还原长片段的结构化资产：

```yaml
scene_type: 都市职场谈判
reader_effect: 压迫感逐步反转为掌控感
techniques:
  - 先用座位、称呼和等待时间建立权力差
  - 主角不解释能力，通过一次可验证判断夺回话语权
  - 反派损失落到项目、职位或人际关系，不用“众人震惊”代替
style_stats:
  dialogue_ratio: 0.47
  median_sentence_chars: 18
  rhetoric_density: low
  narrative_distance: close
avoid:
  - 大段职业术语说明
  - 每句对白后追加动作标签
rights:
  source_class: licensed-derived
  reversible_quote: false
```

### 5.2 检索不是按“相似小说名”，而是按创作任务

查询应拆成以下维度：

- 题材与子题材；
- 当前场景功能；
- 人物关系阶段；
- 视角、人称和叙事距离；
- 目标节奏；
- 读者期待/本章承诺；
- 当前缺陷（如解释过多、声口趋同）；
- 作者自己的风格指纹。

采用 `BM25/全文检索 + embedding + metadata filter + rerank + MMR 多样性`。返回 3–5 张互补技法卡，而不是 20 段同类原文。运行时默认不把完整参考章节放进 Prompt。

### 5.3 防抄袭与版权门

每次导入和每次生成都要过门：

- `CorpusSource` 保存权利人、来源 URL、license、商业可用、再分发、修改、到期时间、审计人；
- 权利状态不是 `approved` 时，不进入生产索引；
- 检索结果记录 `RetrievalTrace`，可追溯用了哪些技法卡；
- 输出与来源做 n-gram、最长公共子串和语义近似泄漏检测；
- 命中高相似片段时阻断自动写入并重新生成；
- 用户要求“完全模仿某在世作者”时，转译为可选择的高层维度，不直接满足作者克隆；
- 用户删除自有样章或撤回授权后，异步删除索引、派生画像和缓存，并保留删除回执。

### 5.4 第一版最经济的来源组合

1. 内部编辑团队先写 300–500 张中文网文技法卡和正反例，不需要大模型训练；
2. 使用 CC0/公版中文语料建立风格分析管线，但不作为现代网文唯一模板；
3. 建立“上传我的样章 → 只用于本作品”的 Style DNA；
4. 邀请 20–50 位作者签约创作题材样章，每类提供好/坏对照和编辑解释；
5. 等评测证明检索确实改善后，再谈大型版权方授权。

这比先买“十万本小说全文”成本更低、版权风险更可控，也更容易形成 Chevoink 自有壁垒。

## 6. Skill OS 3.0

### 6.1 Skill 包结构

```text
skill-id/
├── SKILL.md                 # 完整主工作流，触发后必须完整加载
├── manifest.json            # 机器可读元数据、权限、版本和预算
├── references/              # 按题材/任务按需读取
├── scripts/                 # 确定性检查，不直接拥有高危权限
├── templates/               # 场景卡、量表、输出 schema
├── evals/                   # 正例、反例、冲突例、回归样本
└── assets/                  # UI 图标等，不进入模型上下文
```

### 6.2 Manifest 必要字段

| 字段 | 作用 |
|---|---|
| `id/name/description/version` | 发现、展示和不可变版本 |
| `owner/source/license` | 内置、用户、Agent、第三方及许可证 |
| `triggers` | 任务类型、用户表达、作品状态、题材、阶段 |
| `negativeTriggers` | 明确不应触发的场景，降低误用 |
| `phases` | research / plan / scene / draft / critique / revision / commit |
| `scope` | global / user / novel / session |
| `inputs/outputs` | 结构化契约 |
| `requiredTools/allowedTools` | 最小权限白名单 |
| `tokenBudget/latencyClass` | 成本和延迟边界 |
| `priority/conflicts/composesWith` | 冲突与组合规则 |
| `evalSuiteId/minScore` | 上线前门禁 |
| `status` | draft / testing / active / deprecated / quarantined |

### 6.3 两级 Router，避免“每轮全查、每轮浪费 token”

#### 第一级：确定性候选召回

使用 TaskSpec、明确关键词、当前选中文件类型、作品标签、当前阶段、用户启用状态和负触发规则，在服务端召回 0–8 个候选，不调用大模型。

#### 第二级：语义裁决

仅当候选超过 1 个或置信度不足时，使用低成本分类模型返回：

```json
{
  "selected": ["cn-webfiction-scene", "anti-mechanical-prose"],
  "reasonCodes": ["WRITE_CHAPTER", "STYLE_RISK_HIGH"],
  "confidence": 0.91,
  "phase": "draft"
}
```

普通任务最多加载 2 个 Skill，高价值复杂任务最多 3 个。若没有有效 Skill，明确返回空，不为了“看起来智能”强行匹配。

### 6.4 触发策略示例

| 用户任务 | 自动触发 | 不触发 |
|---|---|---|
| “写一个都市悬疑大纲” | 题材研究（若无 dossier）+ 长篇规划 + 都市悬疑 | 不加载正文润色 |
| “按大纲续写第 8 章” | 章节桥 + 场景写作 + 连续性 | 不重复联网扫榜 |
| “这段太 AI 了” | 风格诊断 + 证据化局部修订 | 不重新规划整卷 |
| “模仿某作者写一章” | 风格维度提取 + 合规转换 | 不加载该作者全文、不承诺一比一模仿 |
| “第一章里的枪在第十章还能用吗” | 连续性/物品状态 | 不加载文笔 Skill |
| 只改一个错别字 | 无 Skill | 不调用 Router 模型 |

### 6.5 Skill 使用回执

每个 run 保存 `SkillRun`：

- 候选和最终选择；
- 触发 reasonCode 与置信度；
- 加载的文件和 token；
- 是否调用脚本；
- 输出质量信号；
- 用户是否接受/撤销修改；
- 对照组版本。

用户可在任务详情看到“本轮使用：都市场景写作 v1.2、机械感审阅 v1.1”，点击查看触发原因和关闭入口。默认不展示冗长内部 Prompt。

### 6.6 用户和 Agent 创建 Skill

创建流程必须是：

1. 作者描述长期偏好或上传自有样章；
2. Agent 生成 Skill 草稿和测试样例；
3. 静态检查权限、外链、提示词越权、隐私和许可证；
4. 在沙箱中对 3–5 个样例做前后对照；
5. 作者查看 diff，选择“仅本作品 / 我的全部作品”；
6. 发布不可变版本并可随时回滚；
7. 新版本默认不自动替换旧版本，先灰度测试。

Agent 不得因一次临时要求自动创建永久 Skill。只有用户明确要求，或同类偏好重复出现且 Agent 提议后得到确认，才进入创建流程。

### 6.7 首批内置中文网文 Skill Pack

- `cn-project-positioning`：题材、目标读者、读者承诺与差异点；
- `cn-long-outline`：卷级情节弧、承诺—兑现、冲突引擎；
- `cn-scene-task`：目标、阻力、选择、代价、状态变化；
- `cn-webfiction-draft`：按场景任务包写正文；
- `cn-character-voice`：声口、知识边界、回避方式；
- `cn-emotion-grounding`：情绪因果、身体与关系后果；
- `cn-prose-specificity`：抽象判断、空洞修辞和解释复述；
- `cn-style-continuity`：风格漂移与叙事距离；
- `cn-chapter-bridge`：章间动作、知识、情绪与未完成问题；
- `cn-continuity-audit`：设定、时间线、人物、伏笔；
- `cn-anti-repetition`：近期章节结构、意象、句式和钩子重复；
- 各题材扩展：都市、玄幻、言情、悬疑、科幻、历史等。

## 7. 创作研究台：解决“AI 完全不知道自己在写什么”

### 7.1 研究不是默认每次联网

触发研究的条件：

1. 新建作品且只有一句题材描述；
2. 第一次进入新的题材/平台/受众；
3. 开启新卷或重大情节弧，现有 dossier 不足；
4. 核心职业、技术、历史事实影响剧情且记忆库无证据；
5. 作者明确要求联网、拆书、扫榜或参考近期趋势；
6. 质量系统连续发现陈词滥调，而内部技法库没有可靠替代。

不触发：普通续写、局部润色、已存在有效 dossier 的同类章节、纯虚构且不依赖现实事实的场景。

### 7.2 研究产物

`ResearchDossier` 至少包含：

- 目标读者和阅读场景；
- 题材核心承诺与常见弃书点；
- 近期作品只做高层特征对比，不复制文本；
- 可差异化的冲突引擎；
- 职业/地域/时代事实卡及来源；
- 题材语言风险（术语、陈词滥调、过度修辞）；
- 对本书的可执行建议与明确“不采用”；
- 来源、抓取时间、有效期和权利类型。

同一作品后续直接复用，只有来源过期或项目方向改变才增量刷新。

### 7.3 首次创作的渐进式体验

用户仍可以一句话开书，但系统不应直接吐 30 章流水账大纲。推荐流程：

1. 快速生成 2–3 个差异化故事方向，每个说明读者承诺、冲突引擎和风险；
2. 作者选择或让 Agent 推荐；
3. 形成一页 Story Charter；
4. 生成第一卷脊柱和前三章试制计划；
5. 先写第一章/前三章样本；
6. 通过盲评式质量门后再扩完整长纲。

该流程把“产品调研”前移，但不会让新用户先填几十项表格。

## 8. Story Compiler：从故事意图到正文

### 8.1 项目级 Story Charter

每本书维护：

- 一句话承诺；
- 目标读者与平台；
- 主角持续欲望、恐惧、误信和不可退让之物；
- 核心冲突引擎（为何能持续几十/几百章）；
- 关系引擎；
- 题材规则、能力代价与现实边界；
- 情绪底色和允许的变化范围；
- 风格 DNA；
- 明确禁区与反例。

### 8.2 卷级与章节级控制

卷级记录：本卷承诺、阶段性欲望、主要对手、升级方式、必须支付的代价、兑现项和遗留项。

章节级不直接存“本章发生 A/B/C”，而是生成 1–4 个 Scene Task：

```yaml
purpose: 让主角第一次意识到搭档在隐瞒同一失踪者
entry_state:
  action: 主角正在整理遗物
  knowledge: 只知道三名客户互不相识
  emotion: 疲惫，仍把异常当巧合
goal: 从旧手机中找出委托人要删除的照片
obstacle: 手机离线且客户在场监视
choice: 当面拆穿，或偷偷备份
cost: 失去客户信任 / 错过唯一证据
turn: 三部手机里出现同一个被裁掉的人影
exit_state:
  knowledge_delta: 异常从巧合升级为人为抹除
  relationship_delta: 主角开始怀疑搭档
  open_loop: 谁在统一处理这些遗物
style_budget:
  description: low
  dialogue: medium
  rhetoric: low
```

### 8.3 Chapter Bridge

每次续写前生成明确桥接对象：

- 上一章最后一个未完成动作；
- 场景地点和时间是否连续；
- 每个人物当前知道/不知道什么；
- 身体、物品和关系状态；
- 情绪余波应立即体现还是被压抑；
- 本章是否需要接钩，若不接，为什么允许延迟；
- 上两章已使用的开篇和结尾结构，避免重复。

这比只读“上一章摘要”更能解决章节衔接生硬。

### 8.4 分阶段生成，但不暴露流水线负担

内部建议流程：

1. `Prepare`：召回事实、桥接、Skill、技法卡；
2. `Beat`：生成 2–3 个场景推进候选，只在关键节点竞争；
3. `Draft`：根据选中的 Scene Task 写正文；
4. `Check`：确定性检测 + 独立 Critic；
5. `Repair`：只修失败证据，最多 2 轮；
6. `Commit`：写入 ChangeSet，更新桥接和记忆。

普通作者只看到 Agent 正在“准备 / 写作 / 检查 / 完成”，高级用户可以展开查看场景卡和质量报告。

## 9. “去 AI 味”质量模型：从禁词表升级为证据系统

### 9.1 不做全局禁词

“熵、量子、铁锈味”本身不是错误。判断公式应是：

```text
异常风险 = 题材不匹配 × 局部频率异常 × 缺少语义铺垫 × 未服务人物/情节 × 近期重复
```

硬科幻中的“量子”可能完全合理；古言日常场景突然使用“熵增般的寂静”，且全书首次出现、没有角色认知基础，才是高风险。

### 9.2 十二类核心质量信号

| 信号 | 检测内容 | 输出 |
|---|---|---|
| `style_drift` | 分段句长、词汇、叙事距离、修辞密度突然漂移 | 漂移起止段和偏离维度 |
| `orphaned_sophistication` | 华丽词/比喻没有上下文铺垫、意象链或人物视角支持 | 原句、缺失支撑、删/改建议 |
| `plot_progress` | 大量段落没有改变动作、信息、关系、资源或风险 | 无推进段落占比与场景建议 |
| `description_load` | 描写与当前场景功能不匹配 | 可删、可后移、必须保留三档 |
| `emotion_grounding` | 情绪只有标签，没有触发、身体、选择或后果 | 缺失链路 |
| `explanation_echo` | 动作/对白之后又由叙述重复解释 | 重复证据对 |
| `sentence_homology` | 连续同构句、排比、总结式段尾 | 模式和频次 |
| `image_repetition` | 跨章重复眼神、喉结、铁锈味、冷意等意象 | 最近 N 章命中 |
| `character_voice` | 人物句长、词汇、回避方式和知识边界趋同 | 对话归属混淆与样例 |
| `causal_gap` | 转折由作者安排而非人物选择或已知条件导致 | 前因缺口 |
| `chapter_bridge` | 上章终态在下章被忽略或机械复述 | 状态断点 |
| `reader_pull` | 章节没有未完成动作、信息差、关系余波或价值变化 | 缺失类型，不强制悬念句 |

### 9.3 自动检查与模型检查分工

确定性脚本负责：

- 词语/意象频率；
- 句长、段长、对话比例；
- 连续句式和 n-gram 重复；
- 章节开头/结尾结构重复；
- 人名、物品、时间、视角显式冲突；
- 与参考库的文本泄漏。

模型 Critic 负责：

- 因果和动机；
- 情绪是否落地；
- 修辞是否有语境支撑；
- 人物声音和潜台词；
- 描写是否服务当前场景；
- 章节是否兑现读者承诺。

两者合并时，确定性事实不能被模型一句“通过”覆盖；审美信号不能被硬阈值直接阻断发布。

### 9.4 修订策略

1. 先删重复解释与无功能段落；
2. 再补缺失的具体动作、选择或后果；
3. 最后才做词句润色；
4. 只修改证据范围，默认不整章重写；
5. 保留作者刻意的不规则、口语、断句和留白；
6. 每轮修订后重新计算风格漂移，防止“修一段毁全章”。

## 10. 角色与情感：让文本有“血肉”的数据基础

### 10.1 Character Voice DNA

角色卡新增：

- 常用句长和词汇层级；
- 称呼体系；
- 面对压力时是解释、攻击、沉默还是转移；
- 不愿直说的内容；
- 注意世界的方式（钱、秩序、身体、关系、危险等）；
- 3–10 条来自作者确认文本的短声口样本；
- 禁止知道的信息；
- 声音随关系和成长阶段如何变化。

评测可采用“移除说话人标签，让模型/专家判断对白归属”；若主要角色经常无法区分，说明声音尚未建立。

### 10.2 Experience Anchors

AI 没有人类经历，但可以把角色经历变成可调用的具体锚点：

- 第一次被拖欠工资时做了什么；
- 对医院消毒水的反应来自哪段记忆；
- 失去某人后保留了什么习惯；
- 面对权力人物时身体先做出什么反应。

情绪场景优先召回 1–3 个与当下相关的经历锚点，禁止把整份人物档案塞入 Prompt。

### 10.3 情绪因果链

质量门检查：

```text
触发事件 → 人物解释 → 身体/注意变化 → 行动冲动 → 实际选择 → 关系或情节后果
```

不要求每次全写出来，但系统必须知道链条；正文可以只呈现其中最有力的两三个环节。这样能避免“他感到无比悲伤”后没有任何行为变化。

## 11. 前端产品：新增“技能”区域

### 11.1 导航位置

桌面 Work 右侧栏、IDE 活动栏与手机创作区统一增加“技能”，顺序为：

`作品 → 上下文 → 变更 → 记忆 → 技能`

复用同一 Skills 数据源和组件状态，不为 Work、IDE、手机分别实现三套业务逻辑。

### 11.2 技能首页

分四组：

- **本轮已使用**：技能、版本、触发原因、阶段、耗时；
- **本作品已启用**：可排序、启停、锁定版本；
- **系统推荐**：基于题材和近期问题推荐，不自动启用；
- **我的技能**：作者创建、Agent 草拟、导入的技能。

每个卡片只显示名称、用途、状态和作用域；详细说明进入二级页，避免右侧栏拥挤。

### 11.3 技能详情

需要具备：

- 说明、触发条件和明确不触发条件；
- 当前版本、来源和许可证；
- 使用的工具与数据权限；
- 当前作品是否启用；
- 最近运行记录和改善/退化信号；
- 测试沙箱；
- 编辑、复制为我的技能、回滚、删除；
- “为什么本轮没有使用”解释。

### 11.4 创建技能

提供两种入口：

1. **对话创建**：“以后写这个角色时，台词都短一点，但不要变成冷漠。”Agent 先生成草稿，作者确认后保存；
2. **表单创建**：名称、用途、触发、禁用场景、规则、样例、作用域。

手机端使用全屏页或 BottomSheet 完成创建与测试；不要把代码编辑器式复杂界面压进窄侧栏。

### 11.5 写作过程中的轻量反馈

Agent 时间线只显示：

- “已加载：章节衔接、人物声口”；
- “质量检查：发现 2 处机械复述，已局部修订”；
- “题材研究复用：都市悬疑 dossier v2，无需重新联网”。

完整细节折叠，避免用户觉得 Agent 在表演流程。

## 12. 数据模型建议

### 12.1 Skill 域

- `Skill`：逻辑身份、所有者、来源、可见性；
- `SkillVersion`：不可变内容、manifest、hash、license；
- `SkillInstallation`：用户/作品作用域、启用状态、锁定版本、排序；

- `SkillAudit`：权限、提示注入、外链、许可证和人工审核。

### 12.2 文笔库域

- `CorpusSource`：权利与来源；
- `CorpusDocument`：作品级元数据和许可继承；
- `CorpusPassage`：仅在允许存储原文时存在；
- `TechniqueCard`：不可逆抽象技法；
- `StyleProfile`：统计画像；
- `RetrievalTrace`：每轮检索证据；
- `LeakageCheck`：输出相似风险与处置。

### 12.3 创作域

- `ResearchDossier`；
- `StoryCharter`；
- `ArcPlan` / `ReaderPromise`；
- `SceneTask`；
- `ChapterBridge`；
- `CharacterVoiceProfile` / `ExperienceAnchor`；
- `ChapterQualityReport` / `QualityFinding`；
- `WritingExperiment`：A/B 版本、作者选择、后续发布结果。

所有新表必须有 `userId/novelId` 作用域和删除策略；作者私有语料禁止默认进入平台公共索引。

## 14. 模型与成本编排

### 14.1 任务分层

| 层级 | 任务 | 模型策略 |
|---|---|---|
| L0 确定性 | 统计、重复、结构、索引、hash、权利门 | 代码，无模型 |
| L1 轻模型 | 意图分类、Skill 候选裁决、元数据抽取 | 低成本低延迟 |
| L2 主模型 | Story Charter、Scene Task、正文 Draft | 高质量模型 |
| L3 独立 Critic | 因果、情绪、声口、风格漂移 | 与 Writer 隔离，必要时不同模型 |
| L4 专家模式 | 新书研究、前三章试制、重大改卷 | 多候选 + pairwise rank |

### 14.2 预算纪律

- metadata 常驻总量设硬上限；
- 每轮 Skill 主说明最多 2–3 个；
- craft 检索默认 3–5 卡；
- Research Dossier 有 TTL 和版本，不重复联网；
- 普通章节只在高风险点生成多候选；
- Critic 先读确定性信号，减少重复分析；
- 质量修订最多自动 2 轮，仍失败则交作者，不无限自循环；
- 缓存相同 Skill 版本、Story Charter 和稳定风格画像。

### 14.3 用户可见模式

- **快速创作**：单候选、轻检查，适合脑暴与试写；
- **平衡创作**：默认，完整 Scene Task + 一次 Critic；
- **精品创作**：关键章节多候选、独立 Critic、两轮修订和泄漏检查。

模式影响成本与延迟，但事实、版权和用户硬约束不随模式放宽。

## 15. 评测体系与产品 KPI

### 15.1 建立 Chevoink-CN-Fiction-Eval

覆盖至少：

- 题材：都市、玄幻、悬疑、言情、科幻、历史；
- 任务：一句话开书、大纲、第一章、续写、冲突场景、情感场景、改稿、跨 50/100 章续写；
- 风格：直白快节奏、克制现实、轻喜剧、古风、冷硬悬疑等；
- 难例：允许“熵/量子”的科幻、故意华丽的角色视角、无章末悬念的情绪收束章，防止规则过拟合。

每个正式场景至少 5 次运行，冻结模型、温度、Skill 版本、检索库版本、代码 SHA 和 token。

### 15.2 人工盲评量表

每篇由至少 3 位目标题材读者/编辑匿名比较 Agent 2.0、3.0 和人类样本，维度包括：

1. 是否愿意继续读；
2. 情节是否真实推进；
3. 人物是否像有自己的欲望和声音；
4. 情绪是否具体可信；
5. 文风是否稳定；
6. 描写是否服务场景；
7. 是否有明显模板/AI 纹理；
8. 章间衔接是否自然；
9. 整体偏好；
10. 猜测作者为人/AI及理由（只作诊断，不作真值）。

### 15.3 自动指标

- 近 N 章 n-gram、开头、结尾和意象重复率；
- 分段风格漂移；
- 对话归属可辨识度；
- 场景状态变化覆盖率；
- 连续性错误数；
- 质量 finding 的作者接受率；
- 参考文本最长相似片段；
- 生成、检索、评审和修订 token/延迟。

自动分只用于回归和定位，不代替专家总评。

### 15.4 核心产品指标

P0 先测 2.0 基线，再设最终阈值。建议首轮目标：

- 3.0 在同题专家总体偏好中相对 2.0 胜率 ≥65%；
- “明显 AI/机械”专家标记率相对下降 ≥40%；
- 作者把章节改到可发布的平均轮数下降 ≥35%；
- 首次创建作品后完成前三章的用户比例提升 ≥25%；
- 7 日内继续创作率提升 ≥20%；
- 章节发布率、更新发布率和每周有效创作用户提升；
- 版权泄漏阻断率 100%，确认侵权输出 0；
- Skill 命中后实际加载率、完成率和用户关闭率均可观测。

### 15.5 A/B 与灰度

- 以用户维度固定分桶，避免同一本书版本漂移；
- 先 shadow：3.0 只评分不改写；
- 再给内部作者和 opt-in 用户；
- 每个 Skill 可单独开关和回滚；
- Writer、Critic、Craft Retrieval 分别做消融实验，确认改善来自哪里；
- 若“质量分提高但作者接受率下降”，判定量表过拟合，不得扩大灰度。

## 16. 分阶段路线图

### P0：基线、可观测与现有规则纠偏（最高优先级）

交付：

- 扩展现有 `tests/agent-evals` 为中文小说质量基线；
- 对 Agent 2.0 采集 Skill 候选、加载、token、修改接受率；
- 将静态“必须钩子/固定字数/固定节奏”从常驻硬表达降为场景感知软信号；
- 给首次 Draft 增加最小版具体化和风格连续性检查；
- 建立专家盲评后台和脱敏样本流程。

门禁：能回答“2.0 哪些题材最差、Skill 实际加载率多少、哪类规则导致模板化”，不再只凭主观个案推进。

### P1：Skill OS 3.0 与“技能”UI

交付：

- Skill/Version/Installation/Run/Eval 数据模型；
- 两级 Router、负触发、版本锁定和完整加载；
- Work / IDE / 手机统一“技能”区域；
- 内置 6 个基础 Skill；
- 用户创建、Agent 草拟、测试、启停、回滚；
- 第三方 Skill 静态安全和许可证审计。

门禁：同一任务在固定版本下可复现；不相关任务误触发率 <5%；明确写作任务的必要 Skill 实际加载率 ≥95%；关闭后立即生效。

### P2：Story Compiler 与章节桥

交付：

- Story Charter、Reader Promise、Scene Task、Chapter Bridge；
- PREPARE→BEAT→WRITE→CHECK→REPAIR→COMMIT；
- 人物知识状态、情绪余波和近期结构去重；
- 平衡/精品创作模式；
- 章节写入仍走 revision 与 ChangeSet。

门禁：跨 50 章续写中的连续性错误相对 2.0 下降 ≥50%；章间衔接盲评胜率 ≥65%。

### P3：人类感质量门

交付：

- 十二类质量信号；
- 确定性脚本与独立 Critic 合并；
- 证据化问题、局部修订、最多两轮；
- Character Voice DNA 和 Experience Anchors；
- 作者对 finding 的接受/拒绝反馈学习。

门禁：机械感专家标记率显著下降；不会把故意华丽、科幻术语或作者口语误清洗成统一白开水。

### P4：合法文笔库与作者 Style DNA

交付：

- CorpusSource 权利账本和导入审批；
- CC0/公版白名单、作者私有样章；
- 技法卡、风格统计、混合检索和多样性重排；
- RetrievalTrace、泄漏检测、撤权删除；
- 首批 300–500 张内部中文网文技法卡。

门禁：所有生产文档 100% 有权利记录；无来源文本不能进入索引；检索开启组在人评中优于关闭组，且无可识别复写。

### P5：研究台、反馈飞轮与生态

交付：

- Research Dossier 和按需触发/缓存；
- 首三章试制与题材风险分析；
- 作者反馈、发布数据和留存的脱敏关联；
- Skill 市场/团队共享（先邀请制）；
- 与版权方、编辑和签约作者共建现代网文技法库。

门禁：研究触发率、复用率和成本符合预算；不出现每章联网；用户能理解并控制自己的数据如何被使用。

## 17. 安全、隐私与合规

- 小说正文、网页、附件、第三方 Skill 都视为不可信数据，不得改变系统权限；
- Skill 脚本使用工具白名单和资源限额，默认无网络、无任意文件和命令权限；
- 作者私有样章默认不用于训练公共模型、不跨作者检索；
- 所有语料支持来源查询、导出、撤回和删除；
- 日志只保存必要统计、hash 和短证据，不记录完整小说正文；
- 外部网页研究保存来源和引用，不把网页指令当系统指令；
- 在使用条款中明确 AI 生成、用户输入、平台技法库和作者授权内容的权利边界；
- 面向商业使用前，由专业律师复核语料授权协议、生成内容标识和作者数据条款，本方案不替代法律意见。

## 18. Rejected Alternatives

### 18.1 抓取热门网文全文做向量库

拒绝。版权、平台条款、数据删除和输出复写风险高；相似片段检索也容易让 Agent 更像拼贴器，而不是更懂写作。

### 18.2 只加一个超长“去 AI 味 Prompt”

拒绝。会扩大上下文污染，所有题材被同一规范塑形，且无法知道哪条规则是否有效。

### 18.3 全局禁用“熵、量子、铁锈味”等词

拒绝。词汇风险取决于题材、角色认知、频率和语境。禁词只会导致同义替换和误伤。

### 18.4 每章都联网学习高分小说

拒绝。慢、贵、来源不稳定、版权风险高，也会让当下热榜风格覆盖作者自己的书。研究应低频沉淀。

### 18.5 默认多 Agent 写每一章

拒绝。成本和协调错误增加，同源模型互审还可能共同偏向同一种 AI 审美。只在高价值任务启用独立 Critic 或候选竞争。

### 18.6 用 AI 检测器分数作为发布门

拒绝。检测器不稳定且会误判；产品目标是提高真实阅读质量和作者效率，不是追逐一个可被改写绕过的分数。

### 18.7 直接复制 GitHub 中文小说 Skills

拒绝默认复制。即使仓库有开源许可证，也要确认 Prompt、示例小说、引用资料和上游依赖分别受什么许可；只在完成来源、许可证、质量和安全审计后选择性移植。

## 19. 关键 ADR

| ADR | 决策 | 理由 |
|---|---|---|
| ADR-301 | 质量问题按工作流、数据、Skill、评测联合治理 | 单 Prompt 无法稳定解决 |
| ADR-302 | 文笔库以技法卡和风格画像为主，原文为受控证据层 | 降低版权、泄漏和拼贴风险 |
| ADR-303 | Skill 采用 metadata 发现 + 主说明完整加载 + 参考按需加载 | 兼顾可靠执行和上下文成本 |
| ADR-304 | Router 两级化，先确定性召回再语义裁决 | 避免每轮模型路由和 token 浪费 |
| ADR-305 | Scene Task 是章节生成的最小计划单元 | 让情节推进和情感因果先于文辞 |
| ADR-306 | Writer 与 Critic 隔离，但不默认多 Agent | 提高独立性并控制成本 |
| ADR-307 | AI 检测率只作弱观测，不作发布门 | 检测可靠性不足 |
| ADR-308 | 研究按需触发并版本化缓存 | 兼顾质量、时效、成本和版权 |
| ADR-309 | 作者私有风格数据默认不跨用户、不进入公共训练 | 隐私与创作资产保护 |
| ADR-310 | 所有质量问题必须带原文证据和最小修订范围 | 防止审美口号和整章洗稿 |

## 20. Definition of Done

Agent 3.0 不能以“技能页做出来了”或“新增了文笔库”宣布完成。正式完成必须同时满足：

1. 写作任务必要 Skill 的候选、加载、版本和结果全链路可观测；
2. 用户可在桌面和手机查看、创建、启停、测试、回滚 Skill；
3. 新书不再从一句话直接跳到模板化长纲，而能形成 Story Charter 和前三章试制；
4. 续写有 Chapter Bridge，长篇状态变化可追溯；
5. 质量问题有证据、有题材边界、默认最小修订；
6. 文笔库每个来源有可验证权利记录，输出有泄漏检测和撤权删除；
7. 3.0 在冻结同题集上显著优于 2.0，并通过专家盲评；
8. 作者修订轮数、前三章完成率、7 日继续创作率和发布率改善；
9. 成本、延迟、失败和降级路径达到预算；
10. 全功能可按用户灰度、可独立关闭、可回滚，旧作品和旧客户端不受破坏。

---

## 21. 最终建议

Agent 3.0 最应优先做的不是“找更多小说喂给 AI”，而是让 Agent 形成一套可观测的创作判断：为什么这场戏要存在，人物此刻想要什么，阻力具体在哪里，他做了什么选择，付出了什么代价，读者得到了什么新信息，语言为什么必须用这种方式表达。

文笔库能提升上限，但只有在以下前提下才有效：来源合法、检索的是当前创作问题、返回的是技法而不是可复制原文、作者风格有最高优先级、写后有真实评测。否则它只会把现在的“AI 华丽腔”升级成“多个作者片段的拼贴腔”。

建议立即以 P0 和 P1 开始：先建立质量基线并让 Skill 真正触发、加载、可见和可控；随后用 Story Compiler 和人类感质量门解决首次生成和长篇衔接；最后再扩大合法文笔库。这个顺序最有可能在可控成本内直接改善用户第一次写出三章后的真实体验和留存。
