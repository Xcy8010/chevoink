# Agent 任务作用域、参数流与续跑入口修复

日期：2026-09-05。接续 plan/25；不修改用户作品、历史窗口或原有发布平台。

## 根因与边界

1. 旧编排护栏按 spawnedFromSessionId 查询整个会话的所有子窗口，忽略已经持久化的 spawnedFromRunId；新任务前一轮失败也会触发，正文工具被不分目标地拦截。失败窗口又被当作“章节未完成”，诱导模型重新启动旧窗口。另有第三次拦截直接放行的非确定性漏洞。
2. 待办读取及 artifact 更新同样是会话级；新任务和续跑上下文可能取回无关历史清单。继续 API 未拒绝过期入口，使用截短的 inputSummary 恢复输入。
3. 工具参数接收器只按 LF 空行切 SSE，未处理 CRLF/CR 和 EOF 尾帧，损坏帧静默丢弃；供应商 length 被覆盖成 tool_calls。解析提示的 400 字诊断片段没有说明自身被截短，模型因此误判输入截断，并收到与场景工具无关的 chapter_append 建议。截图不能单独证明具体供应商丢了哪一帧，以下修复覆盖可复现的协议缺陷，不将其伪称为每次故障的唯一原因。
4. 正文光标依赖最终定稿/工具卡，而工具卡在完整参数到达后才出现；生成长参数时旧正文的光标持续闪烁。

## 实现

- TaskSpec.id 是任务身份；同一任务的显式继续沿用该 id，新请求生成新 id。任务相关 run、待办（消息及 artifact 双来源）和子窗口均按这一身份解析。旧记录没有身份时只认指定 run，不反向猜测整个会话。
- 仅显式继续构建本任务协作快照；停止/失败不等于未交付，不强迫再次写已完成章节。删除会话级正文硬拦截；保留原有章节版本/写入冲突保护。
- task_send 在执行前及工具内检查当前任务窗口归属，重复尝试不能绕过；task_spawn 只接受当前任务原始用户消息的明确多窗口分工授权，不从历史助手输出取授权。不自动清理、重启或删除旧窗口。
- 继续 API 检查最新 run、所有权、运行状态和并发；恢复完整的原始用户输入，而非 300 字摘要。前端请求返回后校验视图世代，切换会话不能把旧响应注入新窗口。
- SSE 按行增量解帧，覆盖 CRLF/LF/CR、UTF-8 跨块、多行 data、尾帧；损坏事件/提前 EOF/非字符串参数安全失败，不静默拼出损坏工具。保留 length 并标记 incomplete；执行时拒绝缺失尾部的结构，旧兼容解析函数的历史修复模式不用于工具执行。
- JSON 正常路径直接解析；完整结构的语法错误通过固定版本 jsonrepair 3.15.0 修复再做原有工具 schema 校验。场景描述明确短句、变化状态及完整 1–4 场景链，状态和风格元数据允许省略，不以丢弃场景正文来换成功。参数失败反馈给真实长度与工具专属修正方向，不回显私人原始参数；同工具连续三次参数失败安全停止，成功后重置计数。
- 正文彻底不渲染闪烁竖线，任务/思考状态仍独立显示。删除聊天正文里的继续按钮；空草稿且可续跑时输入框右下角显示 Play，运行后 Stop；有新文本、引用或附件时不偷偷继续旧任务。保留手机 44px 触控尺寸、忙态互斥与双击锁。

## 参考与取舍

通过 OpenAI Docs 技能核对 [Codex App Server](https://learn.chatgpt.com/docs/app-server) 的显式 thread/resume、turn/start 和 turn/interrupt 边界：恢复有明确 ID 的线程/轮次，不意味着激活同一个会话树里全部历史任务。本项目使用自己的 TaskSpec.id + runId 对应任务/运行，不照搬 Codex 的协议或预算参数。

格式修复采用 [jsonrepair 官方项目](https://github.com/josdejong/jsonrepair) 的确定性语法修复；不增加额外模型调用、不上传参数到第三方服务，也不将补全半份写入内容作为成功。

## 验证与发布

- 回归：当前19章/旧13章隔离、原任务子窗口仍可续派、新任务不注入护栏、遗留无身份记录、四次重复跨任务投递、原始分工授权/否定指令、待办双来源隔离、过期继续 API、原始长输入恢复、连续调用互斥。
- 协议：逐字节中文 UTF-8、三类换行、末尾无空行、多行 data、损坏帧、提前 EOF、length、嵌套 JSON 缺逗号/尾逗号及不完整执行拒绝。
- UI：真实组件测试及 Playwright 1440px/375px 浏览器检查，启动/停止/草稿发送、正文无光标；截图位于 output/playwright/agent-resume-*.png（本地 QA 产物）。浏览器使用模拟任务，未消费线上模型额度。
- 发布前执行 typecheck、test、build、lint 四闸，再推送并等待带 PostgreSQL 的 CI；部署前检查活动任务与回滚备份，确认允许中断后才发布。部署后验证健康检查与实际部署源码/静态资源。
- 不承诺模型永不生成坏参数；协议、授权和不完整写入的确定性边界由服务端测试保证。新语法修复依赖为 MIT、精确锁定版本；项目既有依赖审计警告另行记录，不在本修复中批量升级。
