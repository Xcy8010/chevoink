# 16-手机端创作区 UI/UX 深度优化方案

> 范围：创作中心（/studio、/studio/novel/:id）与沉浸创作（ImmersiveComposer）的**手机端**（<768px）体验重构。
> 铁律：**功能一个不减、桌面端（lg 及以上）布局与交互一行不动**。所有改动收敛在移动端专属分支（`lg:hidden` 分支、`!isDesktop` 分支）与移动端专属组件内。

---

## 0. 问题诊断（来自真实用户反馈 + 代码级审计）

用户原话拆解为四个可验证的产品问题，逐一对应到当前实现：

| # | 用户感受 | 代码层根因 |
|---|---------|-----------|
| P1 | 「界面太紧凑，一个容器套一个容器，视觉疲劳」 | 手机端编辑链路存在**三层视觉容器嵌套**：页面 → `Surface`（padding md + 边框阴影）→ 内层 `rounded-[24px] border px-5 py-5` 卡片 → 正文。360px 宽的屏幕，左右被吃掉 ~48px，正文可用宽度不足 87%。沉浸模式更甚：外层 `px-3` + 卡片 `px-6`，且 `rounded-[28px]` 大圆角在小屏上进一步压缩内容感知宽度 |
| P2 | 「容易点到别的、按钮显得很大很紧凑、不精细」 | 顶栏/工具行按钮 `h-9`/`h-10` 混用、相邻按钮间距仅 `gap-2`(8px)；EditorCanvas 工具行一行塞 4 个按钮（发布/章节设置/保存/沉浸）；小屏（<375px）没有任何压缩档位，`useMobileSize` 已存在但创作区**从未使用** |
| P3 | 「上下滑动不顺畅、不跟手」 | **嵌套滚动**：外层 `overflow-y-auto` 容器内又放了 `textarea` 自己的 `overflow-y-auto`（EditorCanvas L312、ImmersiveComposer L581/L669），iOS 上 textarea 内部滚动无惯性、且与外层滚动链冲突；无 `overscroll-behavior` 治理；键盘弹起无 `visualViewport` 适配，输入点被键盘遮挡后系统强制滚动产生跳动 |
| P4 | 「对比电脑端交互不顺」 | 手机端沿用了桌面 IA：功能入口藏在**左侧抽屉**（汉堡菜单）里，单手拇指热区够不到左上角；抽屉→选项→关抽屉三步才能切视图；沉浸模式手机端顶部一排 5 个横滑 tab pills，既占高度又不符合「沉浸」定义 |

**结论**：不是某个组件的小毛病，而是手机端整体沿用了「桌面卡片工作台」的心智。本方案将手机端创作区重定义为「**全出血单列书写流 + 拇指导航**」。

## 1. 设计原则（本方案所有决策的判据）

1. **纸感优先（Paper-first）**：写作页正文区域是"纸"，纸没有边框、没有卡片、没有阴影。手机端删除一切装饰性容器，只保留一层背景色分区。
2. **单滚动容器（One Scroller）**：任何移动端视图内，垂直方向只允许存在一个滚动容器。textarea 永不内部滚动，改为自动增高随页面滚动。
3. **拇指法则（Thumb Zone）**：高频操作（切视图、保存、发消息）必须落在屏幕下 1/3；低频操作（发布、设置、预览）允许收进「更多」面板。
4. **44pt 触控红线**：所有可点目标实际热区 ≥44×44px（视觉可以更小，用透明热区扩展补足）；相邻可点目标中心距 ≥48px。
5. **小屏降密不降级**：<375px 机型走压缩档（token 降一级），而不是让元素溢出或换行错乱。
6. **跟手动效**：面板出入场一律 `transform` + `opacity`（不触发 layout）；bottom sheet 支持手势拖拽关闭且位移跟随手指。
7. **桌面零回归**：不修改任何 `lg:` 前缀之后的样式与 `isDesktop === true` 分支逻辑；公共组件改动必须以新增 prop（默认值=现状）方式进行。

## 2. 信息架构重构：从「抽屉」到「底部导航」

### 2.1 创作中心手机端 IA（新）

删除现有「左上汉堡 → 抽屉 → 5 个视图入口 + 6 个操作」的模式，改为：

```
┌──────────────────────────────┐
│ 顶栏（44px）：作品切换 ▾ · 保存状态 │  ← 仅两个元素，标题即作品切换入口
├──────────────────────────────┤
│                              │
│         当前视图内容           │  ← 全出血，单滚动容器
│                              │
├──────────────────────────────┤
│  对话   写作   章节   更多      │  ← 底部导航条（56px + safe-bottom）
└──────────────────────────────┘
```

- **底部导航 4 项**（固定，`position: fixed` + `env(safe-area-inset-bottom)`）：
  - `对话`（Agent，默认落地视图，与现状一致）
  - `写作`（EditorCanvas）
  - `章节`（ChapterSidebar）
  - `更多`（半屏 bottom sheet，收纳：作品设置、封面工坊、发布作品/更新发布、沉浸创作、作品页、预览阅读、新建章节——即现抽屉里的全部剩余功能，**一个不丢**）
- **顶栏**：左侧作品名（点击 = WorkspaceNovelSwitcher 下拉，含新建作品）；右侧 SaveStatusPill（compact）。删除汉堡按钮与「对话」pill。
- 现有 `mobileView` 状态机（assistant/editor/chapters/cover/meta）**保留复用**：底部导航映射前 3 项；cover/meta 由「更多」sheet 进入后全屏接管，顶栏出现「‹ 返回」替代作品切换。
- 抽屉代码（`mobileSidebarOpen` 整块）删除。

**决策理由**：拇指单手可达、切视图从 3 步降为 1 步、与 App 端主流创作产品（备忘录/飞书文档/起点作家助手）心智一致。

### 2.2 沉浸创作手机端 IA（新）

沉浸模式在手机端重定义为「**只有纸和一个可收起的工具舱**」：

```
┌──────────────────────────────┐
│ (滚动时自动隐藏) ‹ 退出 · 章节名 · 状态 │ ← 顶栏 40px，下滑隐藏/上滑浮现
│                              │
│   章节标题（输入框，同页滚动）    │
│   正文 textarea（自动增高）      │  ← 无卡片、无边框、全出血 16px 边距
│                              │
├──────────────────────────────┤
│ 字数 · 保存状态     ⌘ 面板  ✓ 保存│ ← 底部工具舱 48px，键盘弹起时吸附键盘上方
└──────────────────────────────┘
```

- 删除现有横滑 tab pills 行（写作/作品/Agent/封面/设置）。
- 「⌘ 面板」按钮打开**全屏 bottom sheet**，内部为分段控件切换：章节 / Agent / 封面 / 设置（即原 4 个非写作 tab，功能不减）。sheet 高度 92dvh，支持下拉关闭。
- 顶栏滚动隐藏策略：向下滚动（阅读/书写向后）隐藏，向上滚动 40px 内浮现；聚焦输入时不隐藏底部工具舱。
- `mobilePanel` 状态机保留，仅渲染载体从「tab 切平铺」改为「sheet 内切换」。

## 3. 视觉减压规范（P1 的解法）

### 3.1 容器层级：手机端一律「零卡片」

| 位置 | 现状（手机端） | 目标 |
|------|--------------|------|
| 写作视图 | Surface(padding md) → rounded-24 卡片(px-5 py-5) → textarea | 无 Surface、无卡片。正文区 `px-4`，标题与正文间用 1px `--border-subtle` 细分隔线，其余全部留白分区 |
| Agent 视图 | Surface(padding md) 包裹 WritingAgentPanel | 去掉 Surface 包裹（新增 `bare` 模式 prop，默认 false 保证桌面不变），消息流直接铺在 `--app-bg` 上，仅 composer 有一层浅色底 |
| 章节视图 | 滚动容器内 ChapterSidebar 自带卡片样式 | ChapterSidebar 增加 `bare` 渲染：列表项全宽、分隔线代替卡片边框 |
| 沉浸写作 | px-3 外层 + rounded-28 卡片(px-6 py-6) | 删卡片。正文 `px-4`（≥415px 机型 `px-5`），上下留白靠 spacing 不靠边框 |
| 封面/设置 | Surface 包裹 | 保留浅背景分区但去边框阴影，表单控件间距从 gap-3 提到 gap-4 |

### 3.2 排版 token（仅移动端生效）

- 正文书写字号：`17px / line-height 1.9`（现 `text-sm`=14px 偏小、`leading-8` 偏挤；17px 是移动端长文输入的舒适基准）。
- 章节标题：`18px semibold`；页面级标题 `16px semibold`。
- 辅助信息（字数/保存状态）：`12px`，颜色一律 `--text-tertiary`，不再使用边框 pill 包裹（去容器感）。
- 区块间距节奏：`16 / 24 / 32`（现状大量 8/12 混用造成"密不透气"）。

### 3.3 小屏压缩档（<375px，接入现成 `useMobileSize`）

| Token | standard/large | small (<375) |
|-------|---------------|--------------|
| 底部导航高度 | 56px | 52px |
| 主按钮高度 | 44px | 40px |
| 正文字号 | 17px | 16px |
| 水平页边距 | 16px | 12px |
| 顶栏图标按钮 | 40×40 视觉 / 44 热区 | 36×36 视觉 / 44 热区 |

实现方式：在创作区移动端根节点按 `useMobileSize()` 挂 `data-mobile-size="small"`，用 CSS 变量覆写，**不写散落的三元表达式**。

## 4. 触控与防误触规范（P2 的解法）

1. **热区扩展**：视觉小于 44px 的图标按钮统一加 `before:absolute before:-inset-2` 透明热区（项目已有 press-feedback 体系，扩展为 `touch-target` 工具类）。
2. **工具行减负**：EditorCanvas 移动端工具行从 4 按钮减为 2：`保存`（主）+ `···`（章节设置/发布/沉浸收进 action sheet）。桌面端仍是 4 按钮（用 `lg:` 区分渲染）。
3. **危险/相邻隔离**：任何破坏性操作（删除计划、拒绝 review）与确认按钮间距 ≥16px，且破坏侧永远在左。
4. **防滚动误触**：列表项点击用 `touch-action: manipulation` 消除 300ms 延迟；滚动中的 touchmove 超过 10px 取消 press 态（press-feedback 已有的行为需在新组件沿用）。
5. **review 操作条**（ChapterChangeReview/PlanChangeReview 移动端）：hunk 级接受/拒绝按钮从行内小按钮改为吸底成对大按钮（各占 50%-8px，高 44px），快捷键提示文案在移动端隐藏（现已 `hidden md:inline`，保持）。

## 5. 滚动与键盘工程（P3 的解法，体验成败的关键）

### 5.1 单滚动容器改造

- **写作视图 / 沉浸写作**：textarea 去掉 `overflow-y-auto` 与固定 `min-h`，改为自动增高——优先 `field-sizing: content`（Chrome/安卓），Safari 回退用「隐藏镜像 div 撑高」或输入时同步 `scrollHeight` 到 height 的轻量 auto-grow hook（`useAutoGrowTextarea`，rAF 节流）。页面滚动由唯一外层容器负责。
- 所有移动端滚动容器统一：`overflow-y-auto overscroll-contain [-webkit-overflow-scrolling:touch]`。
- 禁止「滚动容器套滚动容器」：Agent 消息流是该视图唯一 scroller；章节树是章节视图唯一 scroller。
- 高度基准全部改用 `dvh`（动态视口），杜绝地址栏收放导致的跳动。

### 5.2 键盘适配（visualViewport）

新增 `useKeyboardInset()` hook（监听 `visualViewport.resize/scroll`，输出键盘占高）：

- 写作/沉浸：键盘弹起时底部工具舱 `translateY` 吸附到键盘上沿；光标行保持在可视区中部（`scrollIntoView({block:'center'})`，仅在光标将被遮挡时触发，避免打字每帧滚动）。
- Agent composer：吸附键盘上方，消息流自动滚到底。
- 键盘收起后归位 `safe-area-inset-bottom`。

### 5.3 跟手动效

- bottom sheet（更多/沉浸面板/action sheet）：开启 `touchmove` 跟随（translateY = 手指位移，阻尼 0.6 超出部分），松手速度 >0.5px/ms 或位移 >35% 即关闭，否则回弹（180ms ease-out）。
- 视图切换（底部导航）：内容区 `opacity 120ms` 交叉淡入，不做横向滑动动画（避免与页面滚动手势冲突）。
- 全部动画只用 `transform/opacity`；为 sheet 加 `will-change: transform`。

## 7. 工程护栏与实施顺序

**护栏**
1. 所有新样式以 `lg:hidden` 容器为根，或组件新增默认关闭的 prop（`bare`、`variant="mobile"`），桌面渲染路径 diff 必须为空。
2. 每阶段完成后跑 `npx tsc --noEmit`，并在 1280px+ 视口回归创作区主流程（打开作品/写作/保存/Agent 对话/沉浸/发布入口）确认桌面零变化。
3. 新增 hooks（`useAutoGrowTextarea`、`useKeyboardInset`）与 `BottomSheet` 组件放入通用目录，供后续其他页面复用。

**分期**
- **M1（结构，先解决"难受"大头）**：底部导航 + 更多 sheet 替换抽屉；写作/沉浸零卡片化；单滚动容器 + auto-grow textarea。
- **M2（手感）**：键盘吸附、顶栏滚动隐藏、sheet 跟手手势、touch-target 热区体系。
- **M3（精修）**：小屏压缩档、review 吸底操作条、章节列表滚动位置保持、动效统一验收。

**验收机型矩阵**（真机或 DevTools 模拟）
| 机型档 | 视口 | 必测 |
|--------|------|------|
| 小屏 | 360×740 / 375×667 (SE) | 压缩档生效、无横向溢出、底部导航不与手势条重叠 |
| 标准 | 390×844 | 全流程主验收 |
| 大屏 | 430×932 | 拇指热区、留白节奏 |
| 平板下限 | 767px | 仍走移动布局且不破版；768px 起与现状一致 |

**验收标准（DoD）**
- 写作页从进入到输入 500 字全程：无双滚动、无键盘遮挡、无布局跳动（CLS≈0）。
- 任意功能入口 ≤2 次点击可达（现抽屉模式最深 3 次）。
- 所有可点目标热区 ≥44px，误触相邻按钮率（自测 20 次快速操作)为 0。
- 桌面端（≥1024 lg）像素级零变化。

## 8. 明确不做（防止范围蔓延）

- 不改桌面端三栏布局、拖拽调宽、快捷键体系。
- 不引入富文本编辑器（仍是 textarea），本期只解决容器/滚动/键盘。
- 不做横屏手机专门适配（沿用竖屏布局）。
- 不改任何后端接口与数据流；纯前端表现层重构。
