# 18 - 后台管理系统方案（/admin）

> 目标：在 `https://chevoink.chevolink.com/admin/` 提供产品级可上线的运营管理后台，
> 覆盖用户管理、作品管理、帖子/评论审核等管理员级操作。
> 本文档为整体计划与决策记录，**先不落代码**，评审通过后按阶段实施。

---

## 1. 现状盘点（决策依据）

| 现状 | 结论 |
| --- | --- |
| `UserRole` 枚举已有 `admin`，种子账号「启创管理员」role=admin | 角色模型可复用，无需重建账号体系 |
| 种子管理员只有邮箱（admin@chevoink.local），无手机号 | 现有登录仅支持手机号+密码/验证码，管理员**必须新增邮箱+密码登录通道** |
| API 全站无任何 admin 守卫（grep 零命中） | 需新建 `requireAdmin` 中间件，且所有管理接口服务端强制校验 |
| 会话机制：HMAC 签名无状态 token + HttpOnly Cookie（30 天） | 管理后台复用同一会话机制，不引入 JWT |
| `Post.auditStatus` / `Comment.auditStatus` 已存在（pending/approved/rejected），但只在创建时写 pending，从未过滤 | 审核工作流字段现成，补「管理端审核 + 前台过滤 rejected」即可 |
| `User` 无封禁字段 | 需加 `banned_at`（迁移） |
| nginx：`location / { try_files ... /index.html }` | `/admin` 及子路由深链天然可用，**无需改 nginx** |
| 部署：`deploy:prod` 打包工作区 SSH 直传 + 服务端 `prisma migrate deploy` | 后台随主站一起发布，无新部署单元 |

---

## 2. 总体架构决策

### 2.1 形态：主 SPA 内独立分区（已选）

- 前端：现有 Vite SPA 新增 `/admin` 路由族，独立 `AdminLayout`（侧边栏 + 顶栏），
  懒加载单独 chunk，不进主站 AppShell，`useShell: false`。
- 后端：新增 `/api/admin/*` 路由命名空间，统一挂 `requireAdmin` 中间件。
- 不新建仓库、不新建子域名、不引入 Ant Design 等重型框架（复用现有设计令牌 +
  Button/Toast/Dialog/Skeleton 等 ui 组件，保持品牌一致与包体可控）。

**已否决的替代方案**：
- 独立子域名 + 独立构建产物：多一套部署与证书管理，收益为零（单管理员场景）。
- JWT / 独立管理员 token 体系：现有 HMAC 会话已足够，避免双会话体系并存。
- 现成后台 UI 框架：与现有 Tailwind + CSS 变量主题体系冲突，样式割裂且体积膨胀。

### 2.2 管理员认证链路

```
/admin/login（邮箱 + 密码 + 人机验证）
   → POST /api/admin/auth/login
   → 校验通过 createSession() 下发同一套 chevoink_session Cookie
   → 前端进入 /admin，先请求 GET /api/admin/me 判定身份
   → 401/403 → 回 /admin/login
```

安全约束（全部服务端强制，不依赖前端）：
1. `requireAdmin` 中间件：会话有效 + `role === 'admin'` + 未封禁，任一不满足返回 401/403。
2. 管理登录限速：同一 IP+邮箱 5 次失败锁 15 分钟（进程内计数即可，单实例 PM2）。
3. 管理登录复用现有 `auth-captcha` 人机验证。
4. 登录接口只认 `role=admin` 的账号，普通用户邮箱密码正确也拒绝（防用户枚举统一报「账号或密码错误」）。
5. 管理接口响应永不下发 `passwordHash`。

### 2.3 管理员账号与密码（实施阶段 M0 设置）

- 复用现有「启创管理员」账号（admin@chevoink.local）。
- 密码策略：**随机 24 位**，字符集含大小写字母 + 数字 + 特殊符号（剔除易混字符），
  用项目现有 `hashPassword()`（scrypt+salt）落库。
- 设置方式：一次性服务端脚本（本地生成密码 → SSH 执行 node 脚本更新 password_hash），
  明文密码仅记录到 `cert/README.md`（该文件不入库），交付用户后建议自行改一次。
- 后台内提供「修改我的密码」功能（需旧密码）。

### 2.4 封禁机制（新增）

- `users` 表新增 `banned_at TIMESTAMPTZ NULL`（NULL = 正常）。
- 封禁生效点：`getSessionUserId` 之上的统一包装 `getActiveSessionUser()`——
  查用户是否存在且 `banned_at` 为空，进程内缓存 60 秒避免每请求打库；
  被封禁者所有需登录接口（含主站）返回 401，等同强制下线。
- 管理后台本身走同一检查，管理员也可被封禁（超级操作，防误伤：禁止封禁自己）。

## 3. 数据模型变更（手写迁移，沿用项目模式）

迁移文件：`prisma/migrations/2026xxxx_admin_console/migration.sql`

```sql
-- 1. 用户封禁
ALTER TABLE "users" ADD COLUMN "banned_at" TIMESTAMPTZ;
CREATE INDEX "users_banned_at_idx" ON "users" ("banned_at");

-- 2. 管理操作审计日志
CREATE TABLE "admin_audit_logs" (
  "id"          VARCHAR(64) NOT NULL PRIMARY KEY,
  "admin_id"    VARCHAR(64) NOT NULL,
  "action"      VARCHAR(64) NOT NULL,        -- user.ban / novel.take_down / post.approve ...
  "target_type" VARCHAR(32),                 -- user / novel / chapter / post / comment
  "target_id"   VARCHAR(64),
  "detail"      JSONB NOT NULL DEFAULT '{}', -- 操作前后关键字段快照、理由
  "ip"          VARCHAR(64),
  "created_at"  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX "admin_audit_logs_created_at_idx" ON "admin_audit_logs" ("created_at" DESC);
CREATE INDEX "admin_audit_logs_target_idx" ON "admin_audit_logs" ("target_type", "target_id");
```

`schema.prisma` 同步：`User.bannedAt`、`AdminAuditLog` 模型。

## 4. 功能模块与页面结构

### 4.1 路由地图

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/admin/login` | 管理员登录 | 邮箱+密码+人机验证，独立极简布局 |
| `/admin` | 仪表盘 | 核心指标与待办 |
| `/admin/users` | 用户列表 | 搜索 + 筛选 + 分页 |
| `/admin/users/:id` | 用户详情 | 资料、数据统计、管理操作 |
| `/admin/novels` | 作品列表 | 搜索 + 状态/分类筛选 |
| `/admin/novels/:id` | 作品详情 | 章节列表、数据、下架/恢复 |
| `/admin/posts` | 帖子审核 | 审核工作流主阵地 |
| `/admin/comments` | 评论管理 | 按类型筛选、删除 |
| `/admin/logs` | 操作日志 | 审计追溯 |
| `/admin/settings` | 我的设置 | 修改密码 |

`/admin` 与 `/admin/login` 之外一律 `RequireAdmin` 守卫；`/admin/login` 已登录管理员访问时跳回 `/admin`。

### 4.2 仪表盘

- 指标卡：用户总数、作品总数（已发布）、帖子总数、评论总数。
- 近 7 日新增趋势：注册用户 / 新作品 / 新帖（简单柱状或数字列表，不引图表库）。
- 最近 10 条管理操作日志。

### 4.3 用户管理

- 列表：昵称 / 手机号 / 角色 / 注册时间 / 最近活跃 / 状态（正常/封禁）；
  搜索昵称、手机号、邮箱；筛选角色与封禁状态；分页 20/页。
- 详情：完整资料、作品数/帖子数/评论数/粉丝数、注册时间线。
- 操作（全部二次确认 + 写审计日志）：
  - **封禁 / 解除封禁**（封禁需填理由）
  - **修改角色**：user / author / admin（禁止降级或封禁自己）
  - **重置密码**：生成随机临时密码并展示一次（提示用户首次登录后修改）
  - 跳转查看该用户主页 / 作品列表（站内链接）
- 明确不做：删除用户（涉及级联数据面太大，封禁即满足运营需求；如后续需要再单独立项）。

### 4.4 作品管理

- 列表：书名 / 作者 / 状态（draft/published/completed/archived）/ 可见性 /
  字数 / 章节数 / 浏览收藏数 / 发布时间；搜索书名与作者名；筛选状态与分类。
- 详情：作品信息、章节清单（标题/字数/状态/发布时间）、互动数据。
- 操作：
  - **下架**：`visibility=private` + `status=archived`（前台立即不可见，可恢复）
  - **恢复上架**：`visibility=public` + `status=published`
  - **删除章节**（单章违规，不动整书）
  - **删除作品**（危险操作：双重确认输入书名；级联清理章节、收藏、评论计数）
- 明确不做：代作者编辑正文（越权且易误伤，管理定位是审核与处置）。

### 4.5 帖子管理

> 2026-08-12 决策：**审核工作流本期不接入**（用户明确），帖子管理仅做列表与处置。

- 列表：内容摘要 / 作者 / 话题 / 图片数 / 点赞评论数 / 时间；搜索关键词、分页。
- 操作：**删除**（物理删除，连带评论，写审计日志）。

### 4.6 评论管理

- 列表：内容 / 作者 / 目标类型（作品评/章评/帖子评论）/ 目标标题 / 时间；
  筛选目标类型、搜索内容关键词。
- 操作：**删除**（复用现有 `deleteCommentData` 级联与计数逻辑）。
- `auditStatus` 字段保留不动，不做前台过滤。

### 4.7 操作日志

- 全量审计：谁（admin 昵称）、何时、对什么对象、做了什么、理由/快照、来源 IP。
- 只读列表 + 按 action/target_type 筛选 + 分页；不提供删除入口。

## 5. API 设计（/api/admin，全部 requireAdmin）

统一沿用现有 `buildSuccess / buildError` 响应封套与 data-access 分层。

| 方法 路径 | 用途 |
| --- | --- |
| `POST /api/admin/auth/login` | 邮箱+密码登录（限速+人机验证，不走 requireAdmin） |
| `POST /api/admin/auth/logout` | 登出 |
| `GET /api/admin/me` | 当前管理员身份（前端守卫判据） |
| `PUT /api/admin/me/password` | 修改我的密码 |
| `GET /api/admin/dashboard` | 仪表盘聚合指标 |
| `GET /api/admin/users?search=&role=&banned=&page=&pageSize=` | 用户列表 |
| `GET /api/admin/users/:id` | 用户详情（含统计） |
| `POST /api/admin/users/:id/ban` · `/unban` | 封禁 / 解封（body.reason） |
| `PUT /api/admin/users/:id/role` | 修改角色 |
| `POST /api/admin/users/:id/reset-password` | 重置密码（返回一次性临时密码） |
| `GET /api/admin/novels?search=&status=&categoryId=&page=` | 作品列表 |
| `GET /api/admin/novels/:id` | 作品详情（含章节） |
| `POST /api/admin/novels/:id/take-down` · `/restore` | 下架 / 恢复 |
| `DELETE /api/admin/novels/:id` | 删除作品 |
| `DELETE /api/admin/chapters/:id` | 删除单章 |
| `GET /api/admin/posts?search=&page=` | 帖子列表 |
| `DELETE /api/admin/posts/:id` | 删除帖子 |
| `GET /api/admin/comments?targetType=&search=&page=` | 评论列表 |
| `DELETE /api/admin/comments/:id` | 删除评论 |
| `GET /api/admin/logs?action=&targetType=&page=` | 审计日志 |

写操作内部统一走 `recordAdminAuditLog()` 落审计。

## 6. 实施里程碑

| 阶段 | 内容 | 交付物 / 验收标准 |
| --- | --- | --- |
| **M0 账号与安全底座** | 迁移（banned_at + audit_logs）；`getActiveSessionUser` 封禁生效；`requireAdmin`；管理登录接口 + 限速；一次性脚本设置管理员强密码 | 用 curl 以管理员邮箱密码登录成功；普通用户调 /api/admin/me 得 403 |
| **M1 后台骨架** | `/admin/login`、`AdminLayout`、`RequireAdmin` 路由守卫、`/admin/me`、登出、改密页 | 未登录访问 /admin 跳登录；登录后进入空仪表盘 |
| **M2 仪表盘 + 用户管理** | dashboard 聚合接口与页面；用户列表/详情/封禁/角色/重置密码 | 封禁测试账号后其主站登录态失效；审计日志有记录 |
| **M3 作品管理** | 作品列表/详情/下架/恢复/删除作品/删除章节 | 下架后前台作品页与搜索不可见；恢复后可见 |
| **M4 帖子与评论管理** | 帖子/评论列表、删除（本期不接审核流） | 删除帖子后前台 feed 与详情页不可见 |
| **M5 日志与打磨** | 审计日志页；全站空态/加载/错误态/确认弹窗走查；危险操作二次确认 | 全链路手工回归清单通过 |
| **M6 部署交付** | tsc 全绿 → 提交 → 推送 → `deploy:prod`；管理员账密交付用户 | "Deployment finished successfully"，线上验证由用户完成 |

每个阶段内部遵循项目既有执行规范（见 `plan/list/00-统一执行规范.md`）：
手写迁移、`npx.cmd tsc --noEmit` 校验、部署后不自行检查线上。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 无状态会话无法即时踢人 | banned_at + 60s 缓存检查，最迟 1 分钟生效，运营场景可接受 |
| 删除作品级联面大 | 默认用「下架」处置；删除需输入书名双重确认，事务内级联 + 计数修正 |
| 管理接口被枚举爆破 | 登录限速 + 人机验证 + 统一错误文案；所有管理路径服务端 role 校验兜底 |
| CSRF（Cookie 会话） | 同源 SPA + SameSite=Lax，跨站 POST JSON 触发预检被 CORS 拦截；管理接口均为 JSON 请求体 |
| 审核过滤影响主站性能 | auditStatus 过滤只在现有查询 where 里加条件，posts/comments 已有索引可覆盖 |

---

## 8. 明确不做（本期范围外）

- 多管理员权限分级（RBAC）：单管理员场景，role=admin 一把钥匙。
- 内容先审后发（发布即拦截）：保持先发后审，避免影响现有创作者体验。
- 数据统计报表导出、运营位配置、公告系统：后续按需立项。
- 删除用户、代作者改正文：见 4.3 / 4.4 说明。
