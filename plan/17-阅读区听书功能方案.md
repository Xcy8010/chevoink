# 17-阅读区听书功能方案（TTS 朗读）

> 范围：阅读器（/novel/:novelId/read/:chapterId）三端（手机 / 平板 / 桌面）新增「听书」能力：整章朗读、音色切换、语速调节、段落跟读高亮、自动翻章、定时关闭、锁屏播放控制。
> 铁律：**不影响现有阅读体验一行逻辑**；听书为纯增量功能，未开启时阅读器行为与现状完全一致；TTS 服务不可用时入口自动降级，不能出现报错弹窗刷屏。

---

## 0. 竞品拆解：番茄小说等主流产品的听书是怎么做的

| 能力 | 番茄小说 | 起点读书 | 微信读书 | 本方案取舍 |
|---|---|---|---|---|
| 入口 | 阅读页顶栏耳机图标 + 书页外「听书」tab | 阅读页菜单「听书」 | 顶栏耳机图标 | ✅ 阅读页顶栏耳机图标（三端统一心智） |
| 音色 | 多个神经音色（女声/男声/方言/明星音） | 6-8 个精选音色 | 2-4 个 | ✅ 精选 6-8 个中文神经音色，不做长列表 |
| 语速 | 0.5x–3.0x 滑杆 | 档位制 | 档位制 | ✅ 档位制（0.75/1.0/1.25/1.5/2.0/3.0），实现走 `audio.playbackRate` |
| 跟读高亮 | 当前句/段高亮 + 自动滚动 | 段落高亮 | 段落高亮 | ✅ **段落级**高亮 + 平滑滚动居中（正文本来就按段落渲染，句级切分收益低成本高） |
| 自动翻章 | 章末自动续播下一章 | 同 | 同 | ✅ 默认开启，可关 |
| 定时关闭 | 15/30/60/90 分钟 / 播完本章 | 同 | 同 | ✅ 15/30/60 分钟 / 播完本章 |
| 锁屏控制 | 系统媒体通知（播放/暂停/上下段） | 同 | 同 | ✅ Media Session API（Web 能力内最大化） |
| 语音来源 | 自研/火山引擎 TTS（服务端合成） | 讯飞等 | 自研 | ✅ 服务端 Edge TTS 免费合成为主，浏览器 Web Speech 兜底 |

核心结论：主流产品全部是**服务端合成音频 + 客户端播放器**架构，而不是终端 TTS。原因：音色统一可控、支持锁屏/后台播放、播放进度可精确对齐文本。Web 端要对齐这个体验，必须走「后端合成 mp3 → `<audio>` 播放」，而不是 `speechSynthesis` 直读。

## 2. 技术选型：三条路线对比与最终架构

### 2.1 路线对比

| | A. 浏览器 Web Speech API | B. 服务端 Edge TTS 代理（推荐） | C. 云厂商付费 TTS |
|---|---|---|---|
| 成本 | 0 | 0（非官方免费接口） | 按字符计费（腾讯云约 ¥2/万字符） |
| 音色质量 | 看设备：iOS 好、Android WebView 差、桌面 Chrome 一般 | 微软神经音色（晓晓/云希等），与 Edge「大声朗读」同源，**接近番茄水准** | 最好 |
| 音色统一性 | ❌ 每台设备不一样，无法承诺产品体验 | ✅ 全端一致 | ✅ |
| 锁屏/后台播放 | ❌ iOS 锁屏即停，无媒体通知 | ✅ `<audio>` + Media Session，锁屏可控 | ✅ |
| 语速 | utterance.rate | `audio.playbackRate`（0.5–3.0 无损变速） | 同 B |
| 稳定性风险 | 无 | ⚠️ 非官方接口，微软偶尔改签名（rany2 社区通常数日内跟进） | 商用 SLA |
| 长文本 | ⚠️ Chrome 15 秒静音 bug 需 pause/resume hack | 分批合成，无此问题 | 同 B |

### 2.2 最终架构：**B 为主，A 为兜底，C 为远期开关**

```
┌────────── 前端（阅读器） ──────────┐      ┌────────── 后端（Express） ──────────┐
│ useTtsPlayer（播放引擎 hook）        │      │ POST /api/ai/tts/synthesize          │
│  ├─ 段落批次队列（由 paragraphs 切批）│ ───▶ │  ├─ 权限：公开章节放行 / 预览需登录    │
│  ├─ <audio> 双缓冲（当前批+预取下一批）│ mp3 │  ├─ tts-service.ts                   │
│  ├─ playbackRate 语速               │ ◀─── │  │   ├─ provider=edge → @lobehub/tts │
│  ├─ Media Session（锁屏控制）        │      │  │   └─ provider=openai-compatible   │
│  ├─ 段落高亮 + scrollIntoView        │      │  │       （远期付费引擎，同一接口面）  │
│  └─ 定时关闭 / 自动翻章              │      │  └─ 磁盘缓存（同章+同音色+同批次命中）  │
│ 降级：TTS 接口 503 → speechSynthesis │      │ GET /api/ai/tts/voices（音色清单）    │
└────────────────────────────────────┘      └──────────────────────────────────────┘
```

**关键决策（均为定案，实施时不再讨论）**：

1. **语速不参与合成**：合成一律 1.0x 原速 mp3，语速由前端 `audio.playbackRate` 实现。这样缓存键里没有语速维度，缓存命中率最大化，调语速零延迟（番茄同款方案）。
2. **段落批次而非整章合成**：整章 3000+ 字一次合成要等 10s+ 且失败全废。按「累计 ≥600 字或 ≥6 段就切一批」切分（与 `splitReaderParagraphs` 的段落数组对齐，批内记录起止段落下标），首批到达即开播，后台预取下一批，体感「点了就响」。
3. **段落级高亮**：播放器知道当前批覆盖的段落区间；批内按各段字数占批总字数的比例把 `audio.currentTime` 映射到段落下标（误差 ±1 段可接受，成本远低于逐句时间戳）。
4. **服务端磁盘缓存**：键 = `sha1(chapterId + chapterUpdatedAt + voiceId + batchIndex)`，存 `TTS_CACHE_DIR`（默认 `<数据目录>/tts-cache`），LRU 按目录总大小上限（默认 2GB）清理。章节改动后 updatedAt 变化天然失效。热门章节全员命中缓存，Edge 接口调用量被压到最低，也降低被限流风险。
5. **降级链**：`edge 合成失败 → 重试 1 次 → 返回 503 + code TTS_UNAVAILABLE` → 前端捕获后切 `speechSynthesis` 继续读（toast 提示「已切换为本机朗读，音色以设备为准」），并在会话内不再请求后端。全链路失败才提示「听书暂不可用」。
6. **不做的事**：不做逐句卡拉 OK 高亮、不做离线整本下载音频、不做方言/明星音色、不做创作区预览章节的听书（`from=studio` 隐藏入口）。

## 3. 后端设计

### 3.1 新增文件与接口

| 文件 | 职责 |
|---|---|
| `api/lib/tts-service.ts` | 核心服务：音色白名单、文本切批、调 `@lobehub/tts` 合成、磁盘缓存读写与 LRU 清理、失败重试 |
| `api/routes/ai.ts`（扩展） | 挂 2 个新路由，复用现有 `buildSuccess/buildError/sendRouteError` 模式 |
| `api/config/env.ts`（扩展） | 新增 TTS 环境变量（见 3.4） |
| `shared/contracts/api.ts`（扩展） | `TtsVoice`、`TtsSynthesizeRequest`、`TtsVoicesPayload` 类型 |

### 3.2 `GET /api/ai/tts/voices`

免登录（与阅读公开章节一致）。返回服务端配置的精选音色（写死白名单，不透传微软全量 400+ 音色）：

```ts
type TtsVoice = {
  id: string          // 'zh-CN-XiaoxiaoNeural'
  label: string       // '晓晓 · 温柔女声'
  gender: 'female' | 'male'
  recommended?: boolean
}
```

默认白名单（v1 定案）：晓晓（温柔女声，默认）、晓伊（少女）、云希（青年男声）、云健（沉稳男声）、云扬（新闻男声）、晓辰（知性女声）。响应带 `available: boolean`（TTS provider 未配置或被禁用时为 false，前端据此隐藏入口）。

### 3.3 `POST /api/ai/tts/synthesize`

```ts
type TtsSynthesizeRequest = {
  novelId: string
  chapterId: string
  batchIndex: number      // 第几批（0 起）
  voiceId: string         // 必须在白名单内，否则 400
}
```

处理流程：

1. 校验章节存在且 `status=published & visibility=public`（走现有 reader 同款数据口径）；非公开一律 404，**不做**登录用户读自己私密章节的听书（与阅读页口径一致，预览场景已排除）。
2. 服务端按与前端**同一份切批纯函数**（放 `shared/contracts` 或 shared 工具，双端 import 同一实现，保证批次边界一致）从章节正文算出该批文本；`batchIndex` 越界返回 400。
3. 缓存命中 → 直接 `res.sendFile`；未命中 → 合成 → 落盘 → 返回。响应 `Content-Type: audio/mpeg`，带 `Cache-Control: private, max-age=86400` 让浏览器也缓一层。
4. 限流：同一用户/IP 每分钟最多 20 次合成请求（正常听书 600 字/批 ≈ 3 分钟/批，20 次远超正常消耗，防脚本薅接口）。
5. 响应体是二进制音频，**不走** `buildSuccess` JSON 包装；错误仍走 JSON 错误结构。

### 3.4 环境变量（`.env.example` 同步补充）

```
TTS_PROVIDER=edge                # edge | openai-compatible | disabled
TTS_DEFAULT_VOICE=zh-CN-XiaoxiaoNeural
TTS_CACHE_DIR=                   # 空则用默认数据目录下 tts-cache
TTS_CACHE_MAX_MB=2048
TTS_TIMEOUT_MS=30000
TTS_OPENAI_BASE_URL=             # 远期付费引擎（openai-compatible 时生效）
TTS_OPENAI_API_KEY=
TTS_OPENAI_MODEL=
```

`env.ts` 增加 `ttsProviderMode`：`disabled` 或依赖缺失时 `/voices` 返回 `available:false`，全端入口自动消失——**部署无新增强依赖，功能可一键关停**。

### 4.2 播放引擎要点（`useTtsPlayer`）

- **接入点**：在 `useReaderState` 内实例化并随 state 下发三端布局（与 `activePanel` 同层级），播放器生命周期跟随阅读器路由。
- **双缓冲**：`Audio` 两个实例轮换；当前批开播即预取下一批（fetch → blob → objectURL）；`ended` 事件切换实例无缝续播；批间隙感知 <100ms。
- **章节切换语义**：听书中用户手动翻章 → 停止当前播放并自动从新章第 0 批续播；自动翻章 = 末批 `ended` 且 `autoNext` 开 → `navigate(nextHref)` → 数据就绪后自动续播（引擎里挂「待续播」标记，`reader.currentChapter.id` 变化且匹配时触发）。无下一章 → 状态 `ended`，mini bar 显示「已播完最新章节」。
- **段落高亮映射**：当前批覆盖段落 `[start, end]`，按各段字数在批内的累计占比 × `audio.duration` 得到每段起始时间，`timeupdate`（节流 500ms）反查当前段；高亮段落 `scrollIntoView({ block: 'center', behavior: 'smooth' })`，但**用户手动滚动后 5 秒内暂停自动跟随**（监听现有滚动容器，程序化滚动打标记区分）。
- **高亮样式**：`ReaderArticle` 新增可选 prop `activeParagraphIndex?: number | null`（默认 null = 现状零变化），命中段落加 `background: color-mix(in srgb, currentColor 8%, transparent)` + 圆角 + 过渡，随阅读背景色自适应，不引入新颜色 token。
- **Media Session**：`metadata`（书名/章节名/封面 coverUrl）、`play/pause/previoustrack/nexttrack`（上一段批/下一段批）handler；`positionState` 不设（批次制无全章时长）。锁屏与系统媒体中心可控。
- **定时关闭**：15/30/60 分钟（`setTimeout`，暂停时挂起剩余时长）与「播完本章」（末批 ended 时不续播）。
- **降级 speechSynthesis**：封装同一状态机接口的 fallback driver；utterance 按批喂入；Chrome 长文 15s 静音 bug 用「每批 ≤600 字 + `onend` 链式续播」天然规避；`rate` 映射档位；此模式下隐藏音色选择（显示「本机音色」）。
- **清理**：路由卸载/退出阅读器时 `pause()`、revoke 所有 objectURL、清 Media Session handler、清定时器。

### 4.3 UI / 交互（三端）

**入口（未播放时）**：顶栏耳机图标（`Headphones`），位于「设置」按钮左侧——手机端顶部控制栏、平板端顶栏、桌面端右侧操作列各加一枚。`voices.available=false` 或 `from=studio` 时不渲染。点击 = 立即从**当前阅读位置最近的段落**（取视口内第一个段落所属批次）开始播放，同时弹出 mini bar。iOS 音频解锁：首次 `play()` 必须发生在这次点击的调用栈内（先播一段静音 blob 解锁再换真音频，引擎内置）。

**mini bar（播放中吸底）**：

```
┌──────────────────────────────────────────────┐
│ ▶/⏸   晓晓 · 1.25x        ⏮段 ⏭段   ⏱  ✕   │  ← 高 56px + safe-bottom
└──────────────────────────────────────────────┘
```

- 手机端：`fixed` 吸底，z 在阅读器控制栏之上；控制栏呼出时上移让位（`translateY` 联动 `controlsVisible`）。点击 bar 主体展开 `TtsControlSheet`（复用现有 `BottomSheet`）。
- 平板/桌面端：吸底居中悬浮胶囊（max-width 480px，圆角 pill，阴影），点击展开：平板用 BottomSheet，桌面用现有 Popover 模式挂在 bar 上方。
- ✕ = 停止并收起（回到未播放态）；⏱ 图标在定时激活时显示剩余分钟数。

**控制面板（TtsControlSheet）**：音色（2 列网格，每项：名字+性别标签，选中描边品牌色，切换音色 = 清预取缓存从当前批重播）、语速（6 档 pill：0.75/1.0/1.25/1.5/2.0/3.0）、定时关闭（不开/15/30/60/播完本章）、自动播放下一章（Switch，默认开）。所有变更即时生效并持久化。

### 4.4 机型与平台适配清单

| 场景 | 处理 |
|---|---|
| iOS Safari 自动播放策略 | 首次播放在用户手势内解锁（4.3）；自动翻章续播复用已解锁的 Audio 实例，不会被拦 |
| iOS 锁屏/后台 | `<audio>` 播放不中断；Media Session 提供锁屏控制；**不承诺**息屏数小时连播（iOS 可能回收页面，属 Web 平台边界，文案不宣传「整晚听书」） |
| Android Chrome/微信内置 | 微信 X5 对 blob URL 音频兼容良好；仍在手势内解锁；微信后台播放受限时暂停即可，恢复前台可继续 |
| 小屏 <375px | mini bar 隐去音色文字只留图标；批次跳转按钮保留 |
| 横屏/桌面 | 悬浮胶囊居中，不遮正文（正文 max-width 680，bar 与其对齐） |
| 安全区 | mini bar `padding-bottom: env(safe-area-inset-bottom)`，与现有阅读器底栏同法 |
| 弱网 | 下一批预取失败静默重试 2 次；当前批播完仍没拿到 → mini bar 转 loading 态，拿到即续播；连续失败走降级链 |
| 无障碍 | 入口/控制按钮全部 `aria-label`；mini bar `role="region" aria-label="听书播放器"` |

## 5. 数据契约变更汇总

- `shared/contracts/api.ts`：`TtsVoice`、`TtsVoicesPayload { voices, available, defaultVoiceId }`、`TtsSynthesizeRequest`。

## 6. 分期执行

### M1（一次交付可用的完整听书）
1. 后端：`tts-service.ts` + 2 路由 + env + 缓存 + 白名单音色（依赖 `@lobehub/tts`，失效备选 `node-edge-tts`）。
2. shared：切批纯函数 + 契约类型。
3. 前端：`useTtsPlayer`（含双缓冲、语速、定时、自动翻章、段落高亮跟随）+ mini bar + 控制面板 + 三端入口 + 设置持久化。
4. 验收后部署（tsc → deploy-production.ps1 → 线上验收）。

### M2（体验加固）
1. Media Session 锁屏控制 + 封面元数据。
2. speechSynthesis 降级 driver + 全链路失败文案。
3. 合成限流、缓存 LRU 清理巡检、慢请求日志。

### M3（远期，默认不做）
- `TTS_PROVIDER=openai-compatible` 接付费引擎（火山/腾讯云的 OpenAI 兼容网关），只改 env 不改代码。
- 听书进度云端同步、整本连播队列。

## 7. 验收清单

- [ ] 手机端：点击耳机 → 1.5s 内出声；正文当前段高亮并自动跟随；手动滑动 5s 内不抢滚动。
- [ ] 切音色立即从当前批重播；调语速即时变速不重新加载。
- [ ] 章末自动进入下一章并续播；最后一章播完提示明确。
- [ ] 定时 15 分钟到点停止；「播完本章」在章末停止。
- [ ] iOS Safari：锁屏继续播，锁屏界面可暂停/继续。
- [ ] 断网：当前批播完后 loading，恢复网络自动续播。
- [ ] `TTS_PROVIDER=disabled` 部署后：全端看不到听书入口，阅读器其余功能零回归。
- [ ] 同一章同一音色第二个用户收听：后端日志显示缓存命中，无 Edge 调用。
- [ ] 桌面/平板：悬浮胶囊不遮挡正文与现有面板；Popover/Sheet 正常。

## 8. 风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| Edge TTS 非官方接口失效（签名变更/限流） | 中 | ① 依赖库社区通常数日内修复，届时 `npm update` + 重部署；② 磁盘缓存让存量章节不受影响；③ 降级 speechSynthesis 保底可用；④ 远期 M3 付费引擎开关 |
| iOS 息屏长时间后页面被回收 | 中 | 不宣传整晚连播；恢复前台时引擎从当前批重建，体验为「回来点一下继续」 |
| 长章节（>1 万字）批次多、缓存体积大 | 低 | 600 字/批 ≈ 30s mp3 ≈ 240KB；1 万字 ≈ 4MB/音色/章，2GB 缓存可容纳约 500 章·音色组合，LRU 足够 |
| 微软音色白名单个别下线 | 低 | `/voices` 是服务端配置，下线即从白名单移除；用户已持久化的失效音色回退默认晓晓 |
