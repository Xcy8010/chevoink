## 1. 现状诊断总览

### 1.1 当前界面问题清单

经过对全部页面组件的逐一审查，当前 UI/UX 存在以下核心问题：

| 严重程度 | 问题 | 影响范围 |
|---------|------|---------|
| **P0** | 设计令牌使用不一致，部分页面硬编码颜色 | MessagesPage、ReaderPage 等 |
| **P0** | 首页信息架构类似仪表盘，缺乏阅读产品应有的内容导向 | Home.tsx |
| **P0** | 阅读器缺少沉浸体验和阅读进度感知 | ReaderPage.tsx |
| **P1** | 社区页像博客后台而非内容社区 | CommunityPage.tsx |
| **P1** | 消息中心缺乏对话感和即时通讯特征 | MessagesPage.tsx |
| **P1** | 圆角尺寸混乱（18px/20px/24px/26px/28px/32px 六种并存） | 全局 |
| **P1** | 缺少骨架屏加载状态，白屏等待感明显 | 全局 |
| **P2** | 暗色模式实现方式不统一（CSS 变量 vs Tailwind dark: 类混用） | 全局 |
| **P2** | 空状态缺少插画和情感化设计 | 全局 |
| **P2** | 无动画/过渡系统，交互反馈生硬 | 全局 |

## 2. 三端差异化适配策略

> **核心原则**：不是"一套页面缩三遍"，而是"同一个品牌、三套任务结构"。
> 每种设备类型有独立的交互范式、信息架构和体验重心。

### 设计红线（强制执行）

以下做法在本产品中**一律禁止**，设计审查和代码评审发现即打回：

1. **禁止只做断点缩放**：同一套 DOM + CSS media query 把桌面页面压缩到手机宽度，只改宽度不改结构。
2. **禁止只挪位置不改交互**：手机端做成"桌面元素换个排列"，而不是按触控手势重新设计交互路径。
3. **禁止三端共用同一套信息密度**：手机端硬塞桌面端信息量，或电脑端只是手机端放大留白。
4. **禁止忽略输入方式差异**：手机端依赖 hover 态、电脑端缺键盘快捷键、平板端不支持横竖屏切换。

每个页面上线前必须回答三个问题：

- 手机上核心按钮在单手拇指热区内吗？还是把桌面端按钮缩小了事？
- 平板利用了大屏双栏优势吗？还是只是手机版拉宽？
- 电脑支持键鼠高效操作（快捷键/hover/多栏）吗？还是只是手机版放大？

### 2.1 设备定位与任务模型

三种设备不是"屏幕大小不同"，而是**用户场景和任务重心完全不同**：

| 维度 | 手机 (< 768px) | 平板 (768px - 1279px) | 电脑 (≥ 1280px) |
|------|---------------|----------------------|----------------|
| **用户姿势** | 单手竖握，拇指操作 | 双手横持或桌面支架 | 键鼠，正坐 |
| **使用场景** | 通勤、排队、睡前 | 沙发、床上、桌面 | 书房、工位 |
| **核心任务** | 刷推荐、看小说、轻互动 | 长时间阅读、边读边评、轻创作 | 深度创作、管理、数据运营 |
| **交互范式** | 触控手势 + 底部导航 | 触控 + 分栏双栏 | 键盘快捷键 + 多栏工作台 |
| **内容密度** | 低密度、大间距、大点击区 | 中密度、双栏并行 | 高密度、多栏、悬浮面板 |
| **会话时长** | 碎片化 3-10 分钟 | 中等 15-40 分钟 | 长时 30-120 分钟 |

### 2.2 断点与布局切换策略

```
手机端:  < 768px     → 单列流式 + 底部导航 + 全屏模态
平板端:  768-1279px  → 双栏并行 + 侧边栏可折叠 + 抽屉式面板
电脑端:  ≥ 1280px    → 三栏工作台 + 悬浮辅助栏 + 快捷键
```

**关键决策**：不是用 CSS `media query` 做简单缩放，而是在 **组件级** 判断设备类型，切换不同的**布局组件**。采用以下策略：

- 使用 `useMediaQuery` Hook 或 `window.innerWidth` 检测断点
- 同一页面在不同断点下**渲染不同的子组件树**
- 共享数据层（API 调用/状态管理），但视图层独立

```tsx
// 示例：同一页面，三种布局组件
function HomePage() {
  const device = useDeviceType() // 'mobile' | 'tablet' | 'desktop'
  const data = useHomeData()     // 共享数据层

  switch (device) {
    case 'mobile':  return <HomeMobileLayout data={data} />
    case 'tablet':  return <HomeTabletLayout data={data} />
    case 'desktop': return <HomeDesktopLayout data={data} />
  }
}
```

### 2.3 导航系统三端差异

#### 手机端 — 底部固定导航 + 全屏页面

```
┌─────────────────────┐
│  [状态栏]            │
│  [顶部: 品牌+搜索]   │
│                     │
│                     │
│    [页面内容]        │  ← 全屏滚动区域
│    (单列流式)        │
│                     │
│                     │
├─────────────────────┤
│ 首页  消息  [+]  社区  我的 │ ← 底部固定导航
└─────────────────────┘
```

- **5 个 Tab**：首页 / 消息 / [+ 创建] / 社区 / 我的
- 中间 `+` 按钮品牌色填充圆形突出，点击弹出**全屏底部抽屉**
- 每个 Tab 切换为全屏页面替换，无侧边栏
- 导航栏高度 56px + SafeArea 底部间距
- 当前 Tab 图标 + 文字品牌色高亮，未读消息在 Tab 上显示红点
- **手势支持**：左右滑动切换 Tab（可选），页面内下拉刷新

#### 平板端 — 可折叠侧边栏 + 双栏内容

```
┌──────────────────────────────────┐
│  [顶部: 品牌+搜索+头像]           │
├──────┬───────────────────────────┤
│      │                           │
│ [侧  │      [主内容区]            │
│ 边栏 │      (双栏或单栏)          │
│ 导航 │                           │
│ ]    │                           │
│      │                           │
└──────┴───────────────────────────┘
```

- **侧边栏**：默认折叠为图标栏(64px)，点击展开为图标+文字(200px)
- 展开时覆盖内容区（浮层），不推挤布局
- **内容区**：根据页面类型决定双栏或单栏
  - 首页/发现页：双栏内容流
  - 阅读页：正文 + 可切换的目录/评论侧栏
  - 创作页：编辑器 + AI 面板双栏
- 平板横屏时更多使用双栏，竖屏时退化为单栏（接近手机体验但更宽松）

#### 电脑端 — 完整侧边导航 + 三栏工作台

```
┌──────────────────────────────────────────────────┐
│ [顶部: 品牌+搜索+通知+头像]                       │
├────────┬─────────────────────────┬───────────────┤
│        │                         │               │
│ [侧边  │      [主内容区]          │  [辅助面板]    │
│ 导航栏 │                         │  (按需展示)    │
│ 240px] │                         │  280px]       │
│        │                         │               │
│        │                         │               │
└────────┴─────────────────────────┴───────────────┘
```

- **左侧导航栏**：常驻 240px，图标 + 文字，支持收起为 64px 图标栏
- **主内容区**：最大宽度 960px 居中，不被两侧挤压
- **右侧面板**：按页面需要展示（阅读页=目录/评论，创作页=AI 面板，社区=热门话题）
- 右侧面板可折叠，折叠后主内容区扩展
- **键盘快捷键**：支持常用操作快捷键

### 2.4 全局组件三端差异

#### 2.4.1 模态与弹窗

| 设备 | 展示方式 | 说明 |
|------|---------|------|
| 手机 | **全屏底部抽屉** | 从底部滑入，覆盖全屏，顶部有拖拽指示条 |
| 平板 | **居中模态 + 遮罩** | 宽度 480-560px，圆角 16px |
| 电脑 | **居中模态 + 遮罩** | 宽度 520-640px，支持 ESC 关闭 |

**手机端底部抽屉规范**：
- 顶部 12px 处显示 4px×36px 的拖拽指示条
- 支持下拉手势关闭
- 内容区最大高度 85dvh
- 背景遮罩 `rgba(0,0,0,0.4)`，点击遮罩关闭

#### 2.4.2 列表与卡片

| 设备 | 布局 | 卡片尺寸 | 信息密度 |
|------|------|---------|---------|
| 手机 | 单列 | 全宽 - 32px | 低：封面 + 标题 + 1行简介 |
| 平板 | 双列网格 | 半宽 - 24px | 中：封面 + 标题 + 2行简介 + 标签 |
| 电脑 | 3-4列网格 或 横向列表 | 自适应 | 高：封面 + 标题 + 简介 + 标签 + 数据 |

#### 2.4.3 输入与表单

| 设备 | 交互方式 | 说明 |
|------|---------|------|
| 手机 | 全屏编辑页 | 点击输入框跳转全屏编辑页，避免键盘遮挡 |
| 平板 | 底部抽屉表单 | 从底部弹出编辑面板，键盘不遮挡 |
| 电脑 | 内联表单 / 侧边面板 | 在当前页面内直接编辑 |

#### 2.4.4 手势与快捷键

**手机端手势**：

| 手势 | 页面 | 功能 |
|------|------|------|
| 下拉 | 首页/社区 | 刷新内容 |
| 左右滑动 | 阅读器 | 上一章/下一章 |
| 长按 | 书架/作品列表 | 弹出操作菜单(删除/置顶) |
| 双击 | 阅读器正文 | 进入/退出沉浸模式 |
| 轻点中央 | 阅读器沉浸模式 | 呼出控制栏 |

**电脑端快捷键**：

| 快捷键 | 页面 | 功能 |
|--------|------|------|
| `←` / `→` | 阅读器 | 上一章/下一章 |
| `Esc` | 全局 | 关闭模态/退出沉浸 |
| `Ctrl+S` | 创作编辑器 | 保存草稿 |
| `Ctrl+Enter` | 评论/发帖 | 提交 |
| `Ctrl+/` | 全局 | 打开快捷键帮助 |

### 2.7 技术实现策略

#### 2.7.1 设备检测 Hook

```tsx
// src/hooks/useDeviceType.ts
type DeviceType = 'mobile' | 'tablet' | 'desktop'

function useDeviceType(): DeviceType {
  const [device, setDevice] = useState<DeviceType>(() => getDeviceType())

  useEffect(() => {
    const handleResize = () => setDevice(getDeviceType())
    window.addEventListener('resize', handleResize)
    return () => window.removeEventListener('resize', handleResize)
  }, [])

  return device
}

function getDeviceType(): DeviceType {
  if (typeof window === 'undefined') return 'desktop'
  const width = window.innerWidth
  if (width < 768) return 'mobile'
  if (width < 1280) return 'tablet'
  return 'desktop'
}
```

#### 2.7.2 组件级适配模式

```tsx
// 方式一：渲染不同组件（推荐用于差异大的页面）
function ReaderPage() {
  const device = useDeviceType()
  const data = useReaderData()

  if (device === 'mobile') return <ReaderMobile data={data} />
  if (device === 'tablet') return <ReaderTablet data={data} />
  return <ReaderDesktop data={data} />
}

// 方式二：同一组件条件渲染（用于差异小的区域）
function NovelCard({ novel }: Props) {
  const device = useDeviceType()

  return (
    <article className={cn(
      'rounded-lg border',
      device === 'mobile' && 'flex gap-3 p-3',
      device === 'tablet' && 'flex gap-4 p-4',
      device === 'desktop' && 'grid grid-cols-[96px_1fr] gap-4 p-4',
    )}>
      <CoverImage
        src={novel.coverUrl}
        size={device === 'mobile' ? 'sm' : device === 'tablet' ? 'md' : 'lg'}
      />
      <div>
        <h3>{novel.title}</h3>
        <p className={device === 'mobile' ? 'line-clamp-1' : 'line-clamp-2'}>
          {novel.summary}
        </p>
        {device !== 'mobile' && <TagList tags={novel.tags} />}
        {device === 'desktop' && <DataStats novel={novel} />}
      </div>
    </article>
  )
}
```

### 2.8 同端不同机型与方向适配

三个断点只是粗框架，同一设备类别内部不同机型/方向仍需差异化处理。原则是：**功能不少，密度和排版变**。

#### 2.8.1 手机端内部细分

| 细分 | 视口宽度 | 适配策略 |
|------|---------|---------|
| 小屏 | 320-374px（iPhone SE 1代、小屏 Android） | 基础保障线：功能不裁切，但同屏信息量减少；横滑卡片露出 1.2 张即可；标题允许折行；封面尺寸取档位下限 |
| 标准 | 375-414px（iPhone 15、主流 Android） | **设计基准**，所有规格按此出稿 |
| 大屏 | 415-430px+（Pro Max 机型） | 横滑区域多露出半张卡片暗示可滑；网格不做 3 列，只放大卡片间距，避免拥挤 |

- 手机横屏：默认不做专门布局，保持单列居中限宽（最大 560px）；阅读器横屏可做双页翻书效果（P2 可选增强）。
- 底部导航在所有手机尺寸下保证 5 个 Tab 等分不溢出，中间 `+` 按钮不随宽度缩放。

#### 2.8.2 平板横竖屏差异

| 方向 | 视口宽度 | 布局策略 |

- 平板竖屏禁止直接拉伸手机布局，间距、字号、封面尺寸按平板档调整。

## 4. 首页优化方案

### 4.1 问题诊断

当前首页更像一个"内容管理仪表盘"，而非"小说阅读产品首页"：
- 三个小功能卡片（继续阅读/发现更多/打开创作）占据宝贵首屏，但信息量极低
- "正在热读"和"推荐榜"的卡片布局完全相同，无视觉层次差异
- 缺少封面视觉冲击力，所有封面都是缩略小图
- 右侧面板（最新动态/热门讨论/热门话题）像博客侧栏

### 4.2 对标分析 — 番茄小说首页

番茄小说首页核心模块：
1. **顶部 Banner 轮播** — 大图推荐，视觉冲击
2. **分类快捷导航** — 一排圆形图标入口
3. **继续阅读** — 横向滑动的封面卡片
4. **精选推荐** — 大封面 + 简介的纵向列表
5. **排行榜** — 榜单 Tab 切换

### 4.4 各模块详细规格

#### 4.4.1 Banner 轮播

- **尺寸**：移动端全宽，高度 200px；桌面端最大宽度 1200px，高度 280px
- **内容**：封面模糊作为背景底图 + 左侧封面图 + 右侧书名/推荐语/CTA
- **交互**：自动轮播 5s，支持手动滑动，底部圆点指示器
- **动画**：淡入淡出切换，`--duration-slow` + `--easing-default`
- **数据**：取 `recommendedNovels` 前 3-5 本有封面的作品

#### 4.4.2 分类快捷导航

- **样式**：横向滚动，每项一个小图标 + 分类名
- **规格**：图标 40px，文字 12px，间距 16px
- **交互**：点击跳转发现页并带上分类筛选参数
- **数据来源**：后端 `/api/meta` 或从 novels 的 `categoryName` 聚合

#### 4.4.3 继续阅读

- **触发条件**：`continueReading.length > 0` 才显示
- **样式**：横向滑动卡片，每张卡片包含封面(72x96) + 书名 + 进度条 + "第N章" 标签
- **进度条**：底部 2px 色条，颜色 `--color-brand`
- **交互**：点击直接进入上次阅读章节

#### 4.4.4 精选推荐

- **布局**：纵向列表，每项 120x160 封面 + 右侧信息区
- **信息层级**：书名(16px semibold) → 作者(13px secondary) → 标签(Tag 组件) → 简介(14px secondary, line-clamp-2)
- **交互**：整卡可点击进详情页，封面区域 hover 放大 1.02x
- **数量**：首屏展示 4-6 条，底部"查看更多"进发现页

#### 4.4.5 热门榜单

- **Tab 切换**：热读榜 / 新书榜 / 完结榜
- **排行样式**：1-3 名使用特殊色（金/银/铜），4+ 使用常规数字
- **每条内容**：排名 + 封面(56x72) + 书名 + 作者 + 关键数据（字数/在读者数）
- **排序依据**：热读榜按 viewCount，新书榜按 createdAt，完结榜按 archived+wordCount

#### 4.4.6 最新更新

- **样式**：紧凑列表项，无封面或 40x56 极小封面
- **信息**：书名 + 最新章节名 + 更新时间（相对时间格式 "3分钟前"）
- **目的**：给追更用户快速扫读

#### 5.3.5 沉浸模式增强

- 退出方式：轻点屏幕中央呼出浮动控制栏（半透明毛玻璃），点击"退出沉浸"或按 Escape
- 沉浸模式下：隐藏 AppShell 全局导航，正文居中，最大宽度 680px，仅保留进度条和章节名

## 9. 消息中心优化方案

### 9.1 问题诊断

- **颜色体系不统一**：大量使用 `dark:bg-slate-900/70` 等硬编码 Tailwind 类，未使用 CSS 变量
- 会话列表项样式粗糙，选中态过于沉重（整行深色填充）
- 消息气泡无区分度，缺少发送状态
- 无时间分隔线
- 无消息类型区分（文本/小说卡片/系统通知）

### 9.2 优化方案

#### 9.2.1 会话列表

**选中态优化**：
- 从"整行深色填充"改为"左侧 3px 品牌色指示条 + 背景色变浅"
- 选中背景色：`var(--color-brand-soft)`
- 保持文字颜色不变，提升可读性

**会话项结构**：
```
┌────────────────────────────────────┐
│ [头像40px] 会话名称        12:30   │
│            最后一条消息预览...  [3] │
└────────────────────────────────────┘
```

- 头像 40px，昵称 14px medium，时间 11px tertiary
- 消息预览 12px secondary，line-clamp-1
- 未读数：红色圆点 + 数字（>99 显示 99+）
- 在线状态指示：头像右下角 8px 绿点

#### 9.2.2 聊天区域

**消息气泡**：
- 自己发送：品牌色背景 `--color-brand`，白色文字，右侧对齐
- 对方发送：`--surface-muted` 背景，正常文字色，左侧对齐
- 气泡圆角：12px，但发送方右下角 4px，接收方左下角 4px（指向性气泡）
- 最大宽度 70%

**时间分隔线**：
- 超过 5 分钟的消息间隔显示时间分隔
- 居中灰色小字 "12:30" 或 "昨天 15:20"

**消息状态**（发送中/已发送/已读）：
- 发送中：加载图标旋转
- 已发送：单勾 ✓
- 已读：双勾 ✓✓（蓝色）

**消息类型**：
- 文本：标准气泡
- 小说卡片：气泡内嵌入封面 + 书名 + 作者，点击跳转详情
- 系统通知：居中灰色条，非气泡

#### 9.2.3 输入区

- 底部固定，包含：输入框 + 发送按钮
- 输入框自动增高（1-5行）
- 发送按钮：品牌色填充圆形，含发送图标
- 支持 Enter 发送，Shift+Enter 换行
- 扩展：表情按钮 / 图片按钮 / 小说推荐按钮
