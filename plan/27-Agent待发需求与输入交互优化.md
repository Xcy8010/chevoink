## 验收约束

待发需求保留发送时的模型、附件、写作模式等设置；一次只能启动一个会话内任务。普通排队不改变当前任务方向；调整方向必须先停止当前任务，不能并行覆盖作品。新任务和分支发送在本产品会话内完成，不操作 Codex 自身的任务。待发项发生错误须保留并明确显示，不能静默丢失。空白输入框的提示按语义空值判断，不改写用户有效正文。

## 实现与边界

- `AgentQueuedRequest` 保存完整输入快照、版本号、状态和唯一运行关联；相同提交 ID 幂等。领取待发项和创建运行同事务提交。创建新窗口／分支和移动待发项也在同一事务，旧版本操作返回冲突。
- FIFO 使用数据库递增序号，避免同一毫秒提交时随机 ID 导致次序漂移。新窗口同样服从账户并发限制，额度不足时等待可用执行位。
- 保持本项目已有单进程 PM2 Loop 架构。按账户串行化新建、续跑和队列调度的异步准入，统一并发限制；不能直接扩为多进程执行器，扩容须先引入跨进程运行租约。
- 后台每 2 秒检查一次，成功完成后 FIFO 发送；停止、失败和审批等待不自动越过。调整方向提升选中项优先级，abort 当前任务，直到任务注销且持久化终态后才发送。费用、模型或账号校验失败保留为 held，用户可调整方向重试。
- 重启先恢复孤儿运行，再启用队列。已领取的项不会重复创建运行；若崩溃发生在第一条用户消息前，续跑从队列完整输入恢复而不是 300 字摘要。等待中的任务不受浏览器开关影响。
- 前端每 2 秒拉取队列，发现自动启动的新运行后恢复历史并接 SSE；异步回包校验当前会话，避免写入别的窗口。
- 手机操作按钮 44px，队列列表限高滚动；编辑使用独立文本框，不覆盖当前草稿；操作菜单通过 Portal 避免被裁切，并支持 Escape／方向键。恢复条保持直接连接输入框，队列单独在其上方，避免圆角冲突。
- 手机作品选择器使用 visualViewport 定位、左右 8px 安全留白，长标题换行，触摸外部或 Escape 关闭。Portal 显式保留创作区色板，避免半透明透字。
